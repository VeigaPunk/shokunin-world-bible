**F3 — Same-record multi-cause summary is complete only for two vectors (calibration/wording debt).**

The join `'; '`/`', '` is applied only among ambiguous-holder references and in the shape-invalid branch
(`:223-230`, `:276-281`); everywhere else `record_stop_cause = record_stop_cause or …` keeps the
first-detected cause in code order (tick → `from_holder` shape → `to_holder` shape/dangling → `from_holder`
dangling → source). Measured consequence (probes G/H/I/J/L, `r87-probe-multi-invalid`): for mixed
same-record stops the disclosure names one cause and silently omits the others. E1 Template 2 required the
summary to "name them without asserting an unmeasured within-record order"; the landed code asserts code
order. The `r88-shape-ambiguous-armed` README phrase "names the record's complete simultaneous causes" and
the r88 commit message's "same-record simultaneous causes named as a complete summary" are true only for
the shape-invalid+ambiguous vector and for two ambiguous holder fields, not as a general rule. The omitted
findings still print as their own per-field lines, so nothing is lost — the disclosure's claim scope is
what drifts.
