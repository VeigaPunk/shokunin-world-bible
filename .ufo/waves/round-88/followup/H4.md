### Exit-invariance is structural, not only observed

Every `first_stop` assignment is paired with an already-appended error, so the disclosure
line can never be a run's only finding:

- `not sources_available` → `sources.json` failed to load / was not a list, and each of those
  paths appends an error (`check_bible.py:45-56`);
- `item['kind'] != 'item'` → `only valid on item entities` (`check_bible.py:178-179`);
- `entity_id_counts[item['id']] != 1` → `index()` appended `duplicate … id`;
- in-loop causes: invalid tick / from_holder / to_holder, dangling holder, ambiguous holder,
  invalid source_id, `unknown source` (`source()` appends) each append before the stop is set;
  `citation_status == 'unavailable'` implies `sources_available is False`, which already
  appended a loader error.

Scratch control for the one class the corpus does not contain (clean fixture with the source
table removed):

```text
_ctrl-unavail-clean (item-chain-valid minus sources.json)
dfd1fbc  1 finding  exit 1   VIOLATION: sources.json: cannot load JSON: [Errno 2] ...
2ea9ef1  4 findings exit 1   + 3 disclosure lines (source table unavailable)
```

The disclosure widens the report but cannot flip `0 → 1`; the loader error is always present
first. Conversely, nothing that used to exit 1 loses a non-disclosure finding, so `1 → 0` is
impossible. Observed: 150/150 directories keep their exit code.

## Findings & named debt

Harm verdicts on the tested surface (150 directories + 5 probes + 1 control + 9 determinism
runs), per axis:

- **C1 calibration — no harm detected.** The r88 change is a reword-with-merge, not the
  additions-only delta the seat brief expected: the r87 legacy line pair is replaced by one
  merged per-record line, which is why several finding counts fall by one. Coverage is
  preserved exactly (0 records lose disclosure), no non-disclosure finding is lost, exits are
  invariant in all 150 cases and structurally unable to flip, stderr stays empty, and the
  output is deterministic. The claim's three sub-behaviours (shape-invalid arming,
  first-cause tracking, non-holder stops) are each witnessed on the delivered tree. On the
  tested surface the change is therefore at worst neutral, and on the widened stop set it is
  additive-but-true.
- **C2 / C3 axes — not touched by this seat's surface.** The checker reads no prose, so the
  Maya cluster and the inspiration table are out of scope here; `r88-m3-maya-cluster` exits 0
  with the clean footer (schema/citation/relation/timeline path unharmed).

Named debt (documentation, not measured harm):

1. **The r85 receipts are three generations stale.** Anyone diffing `2ea9ef1` against
   `probe-r85-*.txt` sees `28706dc`'s hardening, r87's per-record disclosure and r88's reword
   at once, none of which is the r88 delta. Recommend the round record name
   `B1-tuples.json @ dfd1fbc` as the before-state and mark the receipts as pinned to
   `88c9b1d0…` only.

   `source table unavailable` is an input-provisioning/availability condition, not the
   structure of the delivered records (witnessed at `r61-independent-unavailable` and the

   over-generalisation worth one wording pass.

   changes 2 of them (`r61-independent-empty`, `r61-independent-unavailable`) — additively and

   exits can only be judged as after-state; only the in-corpus probes carry a tree-visible
