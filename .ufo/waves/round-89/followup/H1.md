## Findings & named debt

**F1 — The round's C2 headline "22/22" is rule-dependent and one delivered artifact
misreports it.** `M4-verify.json` reports `after.facts_supported: 22` / `newly_supported: 14`,
but its own recorded before-script (`statement in prose`) returns **8/22 on the delivered
tree** — I re-ran that exact script. The 22/22 figure is correct only under the wave-spec's
grep-anchor rule (14 anchors + 7 pointers + 1 hymn claim), which is a *weaker* rule than
"the claim statement appears in the excerpt". `C7.md:364,368,397-398` already flagged this
("its verification JSON contains a stale R3 string"; "22/22 remains unclosed"). The delivered
tree passes the spec's rule, so this is a record-accuracy defect, not a tree defect.
**Disposition:** any closure text that states 22/22 must name the anchor rule explicitly, and
must not present M4-verify.json's after-block as reproducible by its own script.

**F2 — Documentation-parity gap in the r87 cluster.** `corpus/fixtures/r87-myth-cluster/README.md`
is unchanged at this range and does not mention the four newly delivered excerpts; it names
only `lowwater-hymn-excerpt.md` and `symbolism-clause-map.md`. A reader following the README
cannot discover the new support excerpts, and the only index of them lives under
`.ufo/waves/round-89/` (a work-wave artifact), not in `corpus/knowledge/`. Cheap repair: one
README sentence listing the four excerpts.

**F3 — Two of the three C1 alternatives were not adopted, and the delivered delta matches X1
only.** Verified by hash: delivered checker == baseline + `X1-c1.patch`. X2/X3 patches are
present in the wave dir as evidence but are not in the tree; that is consistent with the
stated plan, and the 4-fixture/0-flip delta is X1's.

**F4 — `.gitignore` does not cover `__pycache__`.** Running `python3 -m py_compile
corpus/fixtures/check_bible.py` inside the repo leaves an untracked `corpus/fixtures/__pycache__/`
(the only ignore entry is `.ufo/interactive-sessions/`). I created and removed it during this
sweep; it is a live hazard for any seat that compiles in place. Not a tree defect today.

**F5 — Environment gap (not a repo defect).** `/tmp` is a 16 G tmpfs whose **inode table was
100 % full** (`df -i`: 1048576/1048576) when this seat started, so a full `git archive` of the
repo into `/tmp` failed with "No space left on device". I fell back to extracting only the
baseline checker (one file) and running it against the unchanged fixture JSON — sound, because
no pre-existing fixture JSON changed at this range. Sibling seats should assume `/tmp` inode
pressure and avoid full-tree copies.

**No harm found on any axis.** No exit flips, no stderr, no new failures among pre-existing
fixtures, no undocumented edits to the checker, no touched fleet docs, no push, no canon
