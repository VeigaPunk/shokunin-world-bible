## Replay and result

Run from the lane root:

```sh
python3 -I .ufo/waves/round-94/work/W22-replay.py
```

Observed at `9c2eea3b58a090f8820c7a723d2f6a22b46ae52b` with Python 3.14.7; checker SHA-256 was the expected `ff9fd2aa6811a813a20bf74d3931d299378bff7f6925576243d2413b857d1421`. The command returned **0** and printed `W22_RESULT PASS fixtures=5 runs=45`. The 9 real CLI variants per fixture were: canonical relative, `./`-relative, trailing slash, absolute, `..` path, `sys.executable` with `-I`, and `python3` without `-I` under `PYTHONHASHSEED=0`, `1`, and `random`. Each subprocess exit and stdout/stderr was captured directly, not through a pipeline.

All 45 runs exited 1, emitted no stderr, retained the fixture's canonical violation count and diagnostic order, and matched the canonical stdout byte-for-byte after a single narrowly scoped normalization. The replay rewrites only the exact quoted missing-JSON path in the `No such file or directory` diagnostic to the canonical relative path; it requires exactly one such rewrite for the one missing file. It compares every remaining stdout byte, exit status, violation count, and stderr exactly. Absolute and `..` argv produced different raw stdout hashes for all five fixtures (10/45 runs total); those differences were only the echoed path. Other variants' raw hashes equaled canonical. Thus raw byte receipts remain invocation-shape-sensitive and must pin argv; behavior did not vary in this bounded matrix.
