## Findings

- **Blocker — missing required registry.** Baseline has no root `SKILL.md` (`git cat-file` exit 128), so none of `boundary_doc_check.py`, `discriminate_check.py`, or `support_check.py` has the required child-lane registry row. `PROTOCOL.md` §Gate standard requires registry rows at that home and says a gate is not conformant until its row exists (`PROTOCOL.md:383-390,403-406`). All three tools can return a verdict; listing them in `corpus/tools/README.md` is not a substitute.
- **High — no qualifying self-test.** The three baseline tool sources contain no `--selftest`, `--self-test`, or equivalent self-invocation. The discriminator's `--checker e97613c` is a live regression-simulation mode, not an isolated self-test; none of the tools asserts both an exit code and a stable finding ID against committed independent expectations. This misses `PROTOCOL.md:370-374`.
- **High — no frozen run for mutable inputs.** Baseline wave-tree enumeration found zero `frozen` or `expected.json` paths. Each tool's verdict depends on mutable files: boundary document/checker/fixtures; discriminator checker, fixture data and fixture README expected output; support tool's cluster map and excerpt files. The discriminator's `PIN` and baseline commit are persisted values, and the boundary checker has a hard-coded checker SHA, but neither substitutes for a committed frozen input snapshot plus expected verdict and SHA-256 for every snapshot input. The support map's expected-inventory declaration is inside the mutable map being checked, not an independent pin. Closure must reject changed inputs as `snapshot_tampered` / `could-not-evaluate`, not compare their verdict (`PROTOCOL.md:375-382`).
- **High — boundary checker still falls short of B3.** The integrated baseline has a checker-hash constant and simple C9 string checks (`corpus/tools/boundary_doc_check.py:389-401`), so R1's earlier statement that the proposal had no hash/C9 checks describes that earlier patch state, not the entire baseline. However, baseline `check_anchors()` accepts any in-range line number (`:262-286`); it does not locate AST/content signatures or bind citations to claim families. C9 is checked by literal positive/negative substrings, not authoritative-prose contradiction analysis matched to checker behavior. B3 explicitly requires content-derived anchors and a cross-check of all C9 predicates (`.ufo/waves/round-92/patches/B3-certify-spec.md:18-22,32-58,69-71`). R1 recorded the earlier proposal falsely certifying an in-range wrong anchor, contradictory C9 text, and changed checker (`.ufo/waves/round-93/R1.md:119-160`); those are mandatory final adversarial cases, not a claim about the current baseline binary.

## Concrete closure checks

1. Add one `SKILL.md` registry row per tool. Record `gate` type, entry command, exit-code-to-`clean|failed|could-not-evaluate` map, self-test command and spelling, persisted-value path, write scope, and owner. Keep the README as usage documentation, not the registry.
2. Add a real self-invocation to each executable. Run its actual CLI against isolated, committed fixtures without network or live-tree writes; assert both the prescribed exit code and a stable expected finding ID. Commit expected values independently of recomputation. Include a clean case and a deliberate regression/failure case for each.
3. For each mutable-artifact verdict, commit a frozen input snapshot and expected verdict under an allowed `.ufo/waves/*/frozen` root. `expected.json` must digest every snapshot input, and the run must verify those digests before evaluating; tampering must produce `snapshot_tampered` / `could-not-evaluate`. Record the exact revision measured and reproduce the frozen expected verdict.
4. For `boundary_doc_check.py`, meet B3's explicit expected-checker-hash interface; derive anchor resolution from content/AST signatures and claim families; check authoritative C9 wording against the corresponding checker branch and reject contradictory legacy wording. On the frozen document/checker, exercise baseline success and mutations for a wrong but in-range anchor, C9 contradiction, changed checker, missing inputs, and invalid invocation. Verify declared status/code behavior and read-only execution.
5. For `discriminate_check.py`, freeze the two fixture trees, their README expectations, delivered checker and the referenced historical checker source/revision. Verify byte-exact outputs, return codes, and the regression finding on the historical checker; prove edits to any snapshot input are rejected before comparison. Do not treat `--checker e97613c` as its self-test.
6. For `support_check.py`, freeze the map and all referenced excerpts; verify both valid support and stable failures (for example, changed inventory and missing/out-of-span anchor). Do not treat an inventory count declared by that same mutable map as the independent pin. Preserve the README's boundary that this lexical support check does not establish overall claim support.
7. Keep all tool descriptions and verdicts scoped to the artifact checked. A tool's self-test demonstrates behavior on fixtures; it must not claim to establish the integrity of its own implementation. Do not add self-hash/self-integrity claims as a substitute for an externally reviewable committed revision and frozen inputs.
