## Findings

- **HIGH — mismatched `--checker` executes before failure.** Baseline `main()` records a failed hash at lines 346–347, but continues into `replay_receipts()` at line 359. Replay invokes the supplied `checker` with `subprocess.run()` at lines 219–224. In a tiny auto-removed scratch tree I supplied a checker with the wrong hash whose only effect was writing `harmless-marker`. The certifier exited 1 and printed the pin failure, but the marker existed and the receipt replay passed. This proves execution-before-failure without running a harmful checker. A failed pin must return before any replay subprocess; testing only the final nonzero exit is insufficient.
- **MEDIUM — lexical traversal and shell injection are rejected, but symlinks escape the fixture root.** `DIRECT_REPLAY`/`LOOP_REPLAY` and `parse_checker_command()` (lines 36–40, 41–50, 93–105) accept only narrow command forms and simple fixture basenames. The replay text is not passed to a shell; the checker is invoked as an argument list (lines 219–224). Probes accepted a valid direct command and rejected `../` traversal and an appended shell command. However, `fixture.is_dir()` (line 214) follows symlinks and no resolved-path containment check exists: a symlink named under `corpus/fixtures/` pointing outside the root passed `is_dir()` and resolved outside. The lexical guard therefore does not close path traversal through links.
- **MEDIUM — comments/fences can supply control evidence.** `markdown_fences()` (lines 45–74) scans fences without excluding HTML comments; `c9_semantics_check()` (lines 402–404) searches raw document text; anchor search also scans raw text (line 263). The scratch probe found both shell/output fences inside an HTML comment and accepted C9 marker strings placed only in a comment. In the combined harmless-marker probe, the comment-wrapped receipt was replayed, while the overall command still failed on the wrong checker pin. This is evidence of spoofable control inputs, not a full end-to-end false-`CERTIFIED` run. Strip or reject comment-contained control material, or rely on and test an immutable exact-document pin before any parsing/replay.
- **LOW — missing paths fail nonzero but escape the intended diagnostic path.** `checker_pin_check()` directly calls `Path(...).read_bytes()` (line 395), so a missing checker raises an uncaught `FileNotFoundError`. For a missing document, `Path(args.doc).read_text()` at line 349 raises before the later guarded document read. Both scratch probes exited 1 with a traceback; the document probe did not reach the intended `FAIL document: cannot read` message. Convert these to deterministic fail-closed findings with no traceback.
- **BOUNDED — caller CWD defines the repository root.** Baseline line 338 uses `Path.cwd().resolve()`. Invoking from another directory changes the default input root and replay `cwd`; the script-root approach should derive one root from `__file__` and consistently resolve defaults, relative overrides, pin reads, and replay against that root.

## Bounded residual requirements for the R01 repair

1. Resolve the checker once; hash and execute that exact resolved path. Abort immediately on unreadable or mismatched pins, before replay or any child process. Exercise this with a harmless marker and assert the marker is absent on pin failure.
2. Anchor the root to the script and use the same root consistently for document reading, checker pinning, fixture lookup, and replay. Define whether absolute `--doc`/`--checker` overrides outside the root are supported; content pinning alone does not impose path containment.
3. Resolve fixture paths and require their real targets to remain within the root (or reject symlinks). Also consider the hash/read-to-subprocess gap: a path can be replaced after its bytes are checked. If concurrent local mutation is in scope, execute a stable copy/descriptor of the verified bytes. The checker is otherwise trusted code with the invoking user's privileges; this gate is not a sandbox or a substitute for a subprocess timeout.
4. Make missing/unreadable document and checker cases structured nonzero failures. Add comment/fence cases to the existing required self-test contract so a comment cannot provide C9 markers, anchors, or receipt blocks. If the new implementation instead pins the whole document, its test must prove changed bytes stop before replay.
5. Keep the certificate bounded: baseline anchor validation only checked cited line ranges, not whether an anchor identifies relevant code. Do not describe a line-range check as AST/content-semantic validation.

These are trust-boundary requirements and bounds, not new scores or a verdict on the concurrent worktree candidate.
