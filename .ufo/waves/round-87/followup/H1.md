bookkeeping hazard, not a code defect — X3's direction (additive, order-preserving) is consistent

Behaviours pinned by these cases:

- The disclosure precedes shape validation, so a **non-dict record after the stop** still gets a

  `record_holder_ambiguous = True` occurs only at `check_bible.py:228,239`, each immediately after an

  a clean chain gets no disclosure (case C).
- The latch and the disclosure are independent of `can_check_chain`/source availability, matching the
  pre-existing global-notice behaviour (cases F and H) — no behavioural regression versus baseline.

## Findings

- **F1 (no harm, primary):** 133/133 inherited tuples byte-identical; no unexpected tuple anywhere.
  Verdict on the inherited-preservation surface: **unchanged** (the desired outcome), with the
  previously silent probe surface gaining declared disclosures.
- **F2 (bookkeeping hazard):** X3's tuple-delta artifact reports a non-delivered wording and
  understates the delivered delta (2 dirs/2 findings vs the delivered 3 dirs/5 findings). X4 is the
  authoritative delta; my sweep reproduces it.
- **F3 (doc drift, not mine to fix):** `corpus/knowledge/holder-assessment-boundary.md:59-63,77,205`
  still states the pre-C1 contract ("exactly one notice per item, located at the FIRST ambiguous-holder
  record", "the single per-item `unassessed` notice"). Stale against the delivered checker. I2's
  `followup/I2.md` and the live-tree modification of that file indicate I2 is refreshing it; my sweep
  independently corroborates the drift. No edit made by H1.
- **F4 (provenance precision gap in I3's artifact):** I3 cites each new fixture's `README.md` as the
  declared-exit source, but only `r87-chain-unique-valid` ("CLEAN with exit 0") and
  `r87-chain-unique-broken` ("chain break and exit 1") declare an exit verbatim. The two masked
  READMEs describe pre-C1 *baseline* behaviour without an exit code, and `r87-myth-cluster/README.md`
  declares none. Observed exits (1, 1, 0) are consistent with the described expectations, so this is a
  provenance precision gap, not a corpus defect.
- **F5 (cosmetic wart, additive):** at the stop record the delivered checker emits both the old global
  notice and the new per-record disclosure, so the origin record carries two overlapping
  "unassessed" lines; the global notice's "at this and all later records" is now redundant with the
  per-record lines. No harm, but worth recording for a later wording round.
- **F6 (consumer surface):** the only tracked consumers of `check_bible` output are documentation —
  `SCORECARD.md:12` ("needs 133-tuple replay"), `SCORECARD.md:57` ("133/133 inherited CLI tuples
  unchanged; 705/705"), `corpus/fixtures/README.md`, `corpus/README.md`. No CI, test runner, or
  grader pins checker output, and `corpus/fixtures/README.md`'s round sections stop at Round 83, so no
  README text describes the new disclosure contract yet. These are the round-artifact refresh targets
  (W1/W2/P1/I2 territory), not H1's.
