## Before → after measurements

This is a spec-only seat: no checker after-state is claimed. The following exit/summary table is the required M2 target, directly from r91 S2's WARN/FAIL and exit contract. Keep current successful-receipt formats unchanged.

| Outcome | Required diagnostic / final result line | Exit |
|---|---|---:|
| No warnings or failures | Final line exactly `RESULT PASS` | 0 |
| Warnings only (including an unreferenced declaration or a missing retelling anchor with valid mode/span) | Each warning has `WARN:`; preserve M2's current final line exactly `RESULT PASS WITH WARNINGS` | 0 |
| Inventory failure: absent, malformed, duplicate, internally inconsistent, or parsed-vs-declared mismatch; includes a valid inventory with no recognized fact rows/header drift | `FAIL:` diagnostic(s), then final line exactly `RESULT FAIL` | 1 |
| Other collected validation failure: source anchor, mode, span, duplicate ID/signature, etc. | `FAIL:` diagnostic(s), then final line exactly `RESULT FAIL` | 1 |
| Cluster/map operational or structural error: missing cluster/map, unreadable/invalidly encoded map, malformed Markdown row shape | `FAIL:` error diagnostic, then final line exactly `RESULT ERROR` | 2 |

`RESULT FAIL` and `RESULT ERROR` are distinct terminal statuses, not substitutes for the `FAIL:` diagnostic. Emit exactly one appropriate terminal result line on every completed checker path; it must be the last summary line. Never emit a pass result when any `FAIL:` was collected. A valid inventory with an unrecognized fact-table header is an inventory/count failure (exit 1), not a generic structural map error; a malformed row whose cell count differs from its header remains a map error (exit 2). These distinctions preserve S2's acceptance cases.

## Findings & named debt

The delivered script deviates on three control-flow paths:

1. **Inventory exceptions are misclassified.** `parse_map()` recognizes the expected-inventory declaration at `corpus/tools/support_check.py:84-88`, then raises `ValueError` for no declaration or an invalid total at `corpus/tools/support_check.py:129-132`. A malformed declaration is effectively absent. `main()` catches these together with map parse/read failures at `corpus/tools/support_check.py:391-395` and returns 2. Inventory absence/malformed/duplicate/inconsistent is required by S2 to be `FAIL` / `RESULT FAIL` / exit 1; only actual map/cluster operational or structural errors are exit 2 / `RESULT ERROR`.
2. **Collected validation failures lack a terminal result.** `run()` prints each `FAIL:` and returns 1 at `corpus/tools/support_check.py:365-370`, without printing `RESULT FAIL`. Fresh in-memory E1 anchor mutation above confirms the final line is only `FAIL: E1: source-support anchor missing`.
3. **Top-level map/cluster errors lack their terminal result.** The missing-cluster and missing-map early returns at `corpus/tools/support_check.py:379-390`, and its exception handler at `corpus/tools/support_check.py:391-395`, print `FAIL:` on stderr and return 2 but do not print `RESULT ERROR`. The fresh missing-cluster/map probes reproduced both cases. Keep their diagnostic context and add the required terminal status.

The README already names these exact deviations at `corpus/tools/README.md:16-21`; it should cease describing them as live debt only after M2's delivered checker is verified against the S2 contract. The `RESULT PASS`, `RESULT PASS WITH WARNINGS`, inventory receipts, and distinct exit-0 baseline behavior above are current and should not regress. No patch integration or larger inventory-format reconciliation is part of this cleanup spec.
