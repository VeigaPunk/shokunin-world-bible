## 2. Seat timing collisions (the three named, plus two more)

Wall span of the 39 reports: first `W2.md` 01:08:19 → last `C6.md` 01:35:06 =
**26.79 min**, median 01:16:19. The seats were genuinely concurrent (largest gap
between consecutive landings 177.7 s). Every named collision is an
**author/verifier ordering** defect, not a missing-file defect.

### 2.1 V2 / X2 — verifier ran before its author

```
V2.md                     01:11:04
patches/X2-c1-alt.patch   01:16:23   (+319 s)
```
V2's verdict (`V2.md:41-47`) is "Blocked: candidate not delivered". True at V2's read
time; the candidate arrived 5m19s later and **was never re-verified by V2**. X2's only
independent check is SE1's receipt spot-check (`SE1.md:27`), not its assigned verifier.

### 2.2 T1 / D1 — same defect, larger gap

```
T1.md                          01:12:15
patches/D1-decision-table.md   01:20:39   (+504 s)
```
T1 performed the prescribed wait-check (two checks, 60 s apart) and still declared
`T1-D1-MISSING (blocked)`; D1 landed 8m24s after T1's report. The identical pair
T2/D2 succeeded (`D2-decision-table.md` 01:15:20 → `T2.md` 01:19:57) only because D2
happened to land early. The 60-second wait window is **~8.5× shorter than the observed
worst-case author latency in this very wave**, so the wait-check cannot do its job.

### 2.3 R1 / V3 — a stale read asserted as current (the sharpest defect)

R1 wrote at **01:29:13**. The delivered `V3.md` (01:21:29) is a **PASS** for X3 and
contains no `BLOCKED_MISSING_TARGET` string:
```
$ grep -rn "BLOCKED_MISSING_TARGET" .ufo/waves/round-87
./R1.md:14:- ... V3 was checked before X3 existed and is explicitly `BLOCKED_MISSING_TARGET` ...
```
R1 cites `V3.md:18-24` for that status; those lines are V3's PASS measurements. R1's
second claim — "V3 was checked before X3 existed" — is also false: `X3-c1-min.patch`
is dated **01:09:08**, twelve minutes before V3's report. Both halves of R1's V3
characterization are contradicted by the delivered tree.

The same stale-read pattern hits R1's own "final inventory", which is presented as
final but is ~21 minutes old:
```
R1.md final inventory says MISSING:  X2 candidate patch, X4 candidate patch, V1-verify.json
delivered mtimes:                    X2-c1-alt.patch 01:16:23, X4-c1-fsm.patch 01:24:30, V1-verify.json 01:27:04
R1.md write time:                    01:29:13
```
All three files existed 5–13 minutes before R1 wrote. **A report's availability claims
are not timestamped against the report's own write time**, so R1 shipped three
false-negatives and one false peer verdict as its final word.

### 2.4 V3 / V1 — verifier-schema convergence missed

V3 (01:21:29) records `MISSING .ufo/waves/round-87/patches/V1-verify.json` as named
debt; `V1-verify.json` landed at 01:27:04 (+335 s). The cross-verifier schema check
that V3 explicitly wanted never happened.

### 2.5 M2 / M1 — a 4-second race

`M1.md` 01:13:20 vs `M2.md` 01:13:24. M2 reports M1's parallel unobservable; M1 landed
4 s earlier. Benign here, but it shows the same class: peer-status claims made from a
single early read.

**Named-debt is correct in every case above** — the seats honestly label their
observations as time-sensitive — but correctness of the label does not repair the
result: two verifications (V2, T1) and one arbitration (R1) were never actually
performed, and the round shipped without them.

## 3. Was the 32–64 seat count justified by the work?

**The declared target is not in the tree, so the number itself is unverifiable.**
Round 86 preserved its regimen (`lore-shokunin/.ufo/rounds/r86/wave-spec.json`,
`wwkd-plan.md`, `wave-validation.json`). Round 87 preserved none:
```

```
No `r87` spec, plan, roster, or `maxLanes` exists. The only in-repo bindings found are
`MISSION.md:55` ("at least 8 L2 subagents per round, in one batched call") and the
32-seat dispatch ceiling in the UFO skill. No "32–64" mandate exists anywhere in the
fleet tree. **Judging 39 seats against a target that was never written down is itself
the finding** — the wave cannot be audited against its own plan.

Judged against the **landed** work, 39 seats is not justified by output volume:

- 2 craft artifacts landed (a 17-line checker hunk + a 9-file fixture cluster).
- 1 of 3 claimed lanes (C2) landed nothing.
- 4 of 6 census seats produced one saturated conclusion.
- 2 of 4 C1 implementations (X2, X4) and 2 of 3 C3 drafts (M1, M2) were discarded;
  X2 and X4 received no verifier PASS.

The count is defensible only as (a) best-of-N search and (b) independent verification.
Both paid off exactly once: C3's M3 selection, and V1's PASS on the shipped C1 hunk.
Neither paid off for C2, and the census lane over-subscribed by ~2–3 seats. A wave of
this size is a *hedge*, and the hedge's realized value here was roughly two seats'
worth of decision-making.

## 4. Three process improvements for r88

### P1 — Author→verifier barrier (fixes §2.1, §2.2, §2.4)

Dispatch verifiers, rankers, and auditors in a **second phase**, on a frozen
author-artifact set, not in the same batch as their authors. If a single batch is
required, replace the fixed 60 s wait-check with a **deadline calibrated to observed
author latency** (in this wave: p100 = 8m24s, so ≥ 9 min) and forbid a verifier from
reporting "blocked" before that deadline elapses. Expected effect: V2 verifies X2, T1
audits D1, V3 sees V1's schema — three missing receipts recovered at zero extra seats.

### P2 — Write-once, versioned seat reports with hashed citations (fixes §2.3)

Seat reports must be append-only per attempt (`<SEAT>-a1.md`, `<SEAT>-a2.md`) or carry
a content hash, and **every cross-seat citation must include the cited file's hash**.
Retain superseded versions. A status claim ("V3 is blocked") must carry the mtime of
the file it was read from. Expected effect: the R1/V3 disagreement becomes decidable —
either R1 cites a superseded `V3-a1.md` hash and is correct about the version it saw,
or the claim is exposed as unsupported. Today the tree cannot tell which, and a
false peer verdict reached the round record.

### P3 — Pre-declared artifact manifest with unique paths (fixes §3 and path collisions)

Publish an exact path/name manifest in the wave spec before dispatch, and give
competing alternatives distinct scratch paths with a single canonical promotion path.
Evidence that this was missing: M1/M2/M3 all wrote the same six-to-nine
`corpus/fixtures/r87-myth-cluster/` paths (M4 had to adjudicate a path collision);
D1 and D2 chose *two different* filenames for one deliverable
(`provenance-chain-decision-table.md` vs `r87-provenance-chain-decision-table.md`),
which C6 and R2 had to reconcile; V4 had to correct guessed F1/F2 suffixes
(`V4.md:8`); W2 fell back because `.ufo/reports/round-1/lore.md` was absent
(`W2.md:5,13`). Expected effect: no wasted seat on name discovery, and one obvious
promotion target for the integrator.

### Also recommended (not among the three)

- **Persist the wave spec.** r86 kept `wave-spec.json`; r87 kept none. Without it the
  seat count, roster, and axis assignment are unauditable (§3).
- **Cap full-corpus replays at two** (one ordinary, one order/isolated-mode variant)
  and convert further census seats into targeted probes. B1/B2/B3/B6 were four copies
  of one result.
- **Make the ranker binding or record its override.** The integrator landed X1 against
  R1's #1 (X3) with no stated reason. Either honor R1 or log the deviation.
