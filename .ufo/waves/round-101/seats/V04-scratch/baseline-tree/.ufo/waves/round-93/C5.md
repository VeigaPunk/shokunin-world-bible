## Findings & named debt

- **Verdict: no ordinary false pass for checker-source drift in a stable checkout.** The new enforced SHA-256 pin catches the concrete out-of-pair mutation even though both fixture outputs and semantic gates still pass. This is stronger than the previous wave-resident check, where the printed hash was informational.
- **Exact bound:** `DISCRIMINATION HELD` means the checker bytes match the pinned digest `ff9fd2aa…` and that (1) a later null `from_holder` after a uniquely-resolved predecessor is definite, and (2) tick `1 <= 3` remains a definite integer inversion with an unresolved expected holder while the distinct chain break remains qualified. The tool also compares these two fixtures to their README outputs and the e97613c baseline. It does not behaviorally exercise every other checker branch; the hash is an identity guard, not a general semantic proof.
- **C5-001 — single-snapshot / test-input integrity bound (unreproduced):** the candidate hashes `check_bible.py` once, then executes that pathname in subprocesses; under concurrent/adversarial mutation after hashing, it does not prove the executed bytes were the hashed bytes. Fixture JSON and README expectations are also read live, not digest-pinned. Under the intended stable-tree use this did not yield a false pass; if concurrent edits or test-fixture tampering are in scope, snapshot/hash-and-execute the checker and pin the two fixture inputs/expectations.
- This tool is the durable two-fixture regression discriminator, not a replacement for the C9 watch's broader source-backed falsification gate or the four scratch C5 scenarios.
