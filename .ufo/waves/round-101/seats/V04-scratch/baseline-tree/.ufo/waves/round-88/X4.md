- Prototyped a rejected-record ambiguity note. When a dict fails the exact provenance-key-set check, inspect its raw `to_holder`/`from_holder` strings only for duplicate admitted entity IDs; emit one local note listing all ambiguous references. Do not set `holder_ambiguity_stop`, do not assert that the rejected object is a provenance event, and do not emit the full per-record disclosure family.
- Strongest case against arming a holder stop here: the checker rejects the whole dict before its field-level validation. Treating one raw field as a semantic holder reference after that rejection lets an inadmissible object mutate cross-record state, and wording later findings as caused by “ambiguous holder identity” can imply a chain event was accepted or that ambiguity—not the rejected shape—caused the comparison gap. A local note accurately reports the raw ambiguity and local non-assessment without resolving the rejected record or promoting its contents into the chain.

## Findings & named debt

- The variant is locally truthful about the rejected record and avoids converting its raw holder value into a chain-stop cause. It does **not** close C1: the malformed row still disables `can_check_chain`, later comparisons remain unassessed without tail disclosures, and no disclosure is added for non-holder stop causes.
- Recommendation: for the semantics question, prefer this rejected-record note over arming the holder-ambiguity stop directly from a rejected dict. Do not treat this narrow variant as a completed C1 fix. A C1-complete design needs a separate structural-stop cause for the rejected record and downstream disclosures that name that actual cause; an ambiguous raw holder value can remain a local observation. If X1’s solution distinguishes those facts in its wording/state, it may satisfy C1 without the overclaim; if it labels the rejected row’s holder ambiguity as the chain’s first semantic cause, the X4 variant is safer.
- After the single 60-second dependency wait-check, B1/B2 baseline artifacts were present but no X1 report or patch was available. Thus this is a conditional design recommendation, not a line-by-line comparison of X1’s implementation.
- Named debt: decide whether C1’s hard tail-disclosure criterion takes precedence over treating rejected rows as semantically inert; then test a separate structural-stop explanation against mixed-stop and non-holder-stop cases. This seat did not change tracked checker code or fixtures.
