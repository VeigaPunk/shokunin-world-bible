## Findings & named debt

- **R87 denominator / row-shape debt:** M1's candidate map has 14 S2 rows (6 entity claims, 4 relations, 4 timeline events) plus eight hymn-symbolism readings, for 22 table rows. It co-maps first-appearance pointers into claim rows and crosswalks the hymn-sourced Mother-Tide Gate pointers at H4. This may cover the 22 distinct JSON pointers, but the 22-row count is not 22 fact-pointer rows; the eight H rows are editorial readings. The R89 JCOV2 census denominator is 22 source-attributed JSON pointers: 7 `first_appearance` + 7 entity claims + 4 relations + 4 timeline events. Preserve the H1–H8 interpretation crosswalk separately (or clearly as non-support metadata), and give each of the 22 JSON pointers its own support row so the receipt has an unambiguous denominator. Relevant candidate evidence: `patches/M1-r87-map.patch:61,75-107,114`; M1 names this denominator mismatch at `.ufo/waves/round-90/M1.md:121`.
- **R88 delivery labels:** M2's map lists both `fictional-excerpts.md` blocks as `verbatim`, but its patch changes only the map, not the excerpt file; neither block has the required excerpt-side label in the baseline. It labels the delivered Spence quote `external-only` in the mode column (`patches/M2-r88m3-map.patch:14-16`), although R9's allowed mode is `verbatim` here. Use `verbatim` for the delivered Spence wording and separately label its external-inspiration/non-in-world scope. The un-delivered underlying K'iche text remains not delivered.
- **M3 support-script contract:** the candidate correctly uses `grep -nF --` and prints paraphrase/summary rows as `retelling-support-only` (`patches/M3-support-script.patch:138-153,179-205`). It still needs integration changes: the CLI accepts one cluster per invocation and the README shows two commands (`:232-246`, `:269-272`); it doesn't enforce the parsed line span (`:80-89` parses it, but `run` never checks it); it counts only rows in the map rather than validating the complete JSON-pointer inventory; and a file-wide “exactly one mode declaration” check (`:127-135`) cannot validate two separately labelled blocks in `fictional-excerpts.md`. Its `SOURCE-SUPPORT` denominator excludes retelling rows, so a source map with an ineligible paraphrase can still report N/N over only the remaining eligible rows. Make the denominator the complete expected fact set; any retelling used for a required source-text claim must remain outside the numerator and fail N/N. Add source-ID/pointer consistency checks and one default command that validates both maps.
- **R87 R3 scope debt:** the charter records a pledged watch, not completed performance. Keep that qualification visible through the map and manual whole-claim review; a lexical match does not decide the JSON relation's meaning. The Gate/Dune accounts of the same vow also remain conflicting and unresolved.
- `check_bible.py` being CLEAN is not a prose/R9 receipt. The ETCSL note is an external, undelivered parallel and cannot support any mapped in-world fact.
