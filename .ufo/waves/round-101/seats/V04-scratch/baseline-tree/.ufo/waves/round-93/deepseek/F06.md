## Findings, severity-ranked

**1. Changed checker rejected before execution — verified, no defect (C1 depth).**
The digest gate (`audit()` lines 451–456) returns before `read_baseline_checker`
and before `replay_receipts`, so no subprocess can reach a drifted checker.
Measured with a side-effect marker appended to a copy of the pinned checker:

- `--checker <drifted+marker>` with the pin unchanged → exit 1, sole finding
  `checker_drift`, **marker absent** (case A2).
- Drifted checker at the **pinned default path** with the pin unchanged → exit 1,
  sole `checker_drift`, **marker absent** (case E).
- Marker-positive twin: same changed checker with the contract pin updated to
  match → exit 0 `CERTIFIED`, 14/14 replay cases, **marker present** (case D).
  This proves the marker line is live and that the pin is the only thing between
  a change and execution — see finding 3.
- Byte-identical alternate `--checker` path → exit 0 `CERTIFIED` (case A1), so
  the refusal in A2 is caused by the digest, not by the override route.
- The finding lists contain no `receipt_*` findings in A2/E, i.e. replay never
  started. Delivered `--self-test` at the candidate: exit 0, all seven cases and
  the `anchor_range_control` pass (baseline_lines=330).

**2. Safe command parse — verified, no injection or traversal path found.**
`parse_checker_command` is `fullmatch`-based with ASCII-only character classes,
and replay executes a list argv (`[sys.executable, checker_path, path]`, no
shell; source scan shows no `shell=`, `os.system`, or `eval(`). Unit probes
refused as `unsupported checker command grammar`: `;`-injected payloads,
`$(...)` in the path position, backticks, `&&`, a second command after the
receipt echo, `corpus/fixtures/../../../../tmp/...`, a `for f in ../../../etc`
loop, `/etc/passwd`, and U+00A0 whitespace. The doc's two real grammars parse.
`is_safe_fixture_path` rejects `..`-bearing, absolute, and out-of-prefix paths.
End-to-end with three hostile blocks injected into the pinned document (pins
updated to match, valid fixtures present): exit 1, `replay_receipts=3/6`,
`FINDING receipt_grammar` at lines 650/660/670, and **both injected markers and
the traversal output file absent**. One grammar quirk, non-exploitable: a loop
name like `--help` parses, but the resulting path is `corpus/fixtures/--help`,
a positional `argv[1]` that cannot become an option.

**3. Mutable-contract trust boundary — real, demonstrated, and already
documented (informational).** Case D shows a changed checker executing and
certifying once the co-located contract pin is edited to match. This is exactly
what `SKILL.md:55` states ("The colocated manifest is not independently pinned
against coordinated edits to both it and the gate") and what R01's bounds say.
Not a hidden hole and not a new harm: the root of trust is repo write access, so
a reviewer must take the gate/contract hashes out-of-band — the hashes are
recorded above and in `F06-evidence.json` for that purpose. The gate itself is
likewise unpinned, and `--self-test` re-invokes the worktree gate
(self-referential), which is part of the same chain.

**4. Special files passed as `--doc`/`--checker` block (low, new observation).**
`--doc <FIFO>` blocked until killed (`timeout 5` → exit 124); a character device
such as `/dev/zero` would read unboundedly. Named failures cover missing,
unreadable, and invalid-UTF-8 inputs only; `/dev/null` correctly yields
`document_drift` and a directory yields `document_unreadable`. Reachability is
local operator argv only (no document- or network-derived path), and no
documented claim promises special-file handling — this is an unlisted bound, not
a falsified claim. Suggested (for L1 to route, not done here): a regular-file
check or size cap, plus a README/SKILL bound note.

**5. `--_test-baseline` is an unverified caller-supplied override
(informational).** In default mode the legacy baseline is read from Git and
digest-checked (`read_baseline_checker` with a flipped pin →
`baseline_checker_drift`). In `--_test` mode the override is used directly and
changes anchor-range outcomes (100-line truncated override → `anchor_range`
unresolved for `check_bible.py:212-224`; true 330-line baseline → 2/2 resolved).
The mode is env-gated (`BOUNDARY_DOC_SELF_TEST=1`), requires both arguments, is
refused when combined with `--self-test`, and is not the certification path —
but it is invisible in `SKILL.md`/README, where only the Git-sourced self-test
path is described. Documentation-only follow-up.
