## argv-embedding / 5-missing-file convention — behavior identity vs bytes

Measured directly (`F02-argv-probes.json`; all exits observed, never piped
away):

| Probe (repo root) | exit | violations | stdout SHA-256 |
|---|---|---|---|
| `… check_bible.py corpus/fixtures/r5-missing-file` | 1 | 1 | `430d8efb…` |
| `./corpus/fixtures/r5-missing-file` | 1 | 1 | `430d8efb…` (byte-equal) |
| `corpus/fixtures/r5-missing-file/` | 1 | 1 | `430d8efb…` (byte-equal) |
| absolute path | 1 | 1 | `7a81d502…` (prefix transform only) |
| `corpus/fixtures/../fixtures/r5-missing-file` | 1 | 1 | `473d7800…` (prefix transform only) |
| `PYTHONHASHSEED=random`, no `-I` | 1 | 1 | `430d8efb…` (byte-equal) |
| nonexistent dir `corpus/fixtures/F02-no-such-dir` | 1 | **5** | `deae4478…` |
| nonexistent dir, absolute | 1 | 5 | `83452129…` (prefix transform only) |
| no positional arg | **2** | 0 | empty stdout, usage on stderr |
| two positional args | **2** | 0 | empty stdout, usage on stderr |

Convention: the checker resolves the five section files
`sources/entities/relations/timeline/contradictions.json` under the
`argv[2]` directory. A missing directory therefore emits exactly **5**
`cannot load JSON: [Errno 2] No such file or directory: '<argv-path>/<section>.json'`
violations in that fixed order, then `5 violation(s); no canon changed`, exit
1, empty stderr. Exactly **5 fixtures** are path-sensitive for the same
reason (each is missing at least one section file):
`r5-missing-file` (contradictions), `r62-missing` (timeline),
`r67-claim-source-unavailable-{control,empty,whitespace}` (sources). For each,
absolute-argv stdout equals relative-argv stdout with the directory prefix
substituted, exit and counts invariant. Fixtures whose stdout contains no
argv-derived path (`ally-one-way`, `r91-c1-null-chain`,
`r93-m2-kojiki-cluster`) are byte-identical under relative and absolute argv.

Explanation (behavior identity vs bytes): the `OSError` text embeds `argv[2]`
verbatim, so **byte identity** of these stdout receipts is
invocation-shape-dependent — `./`-prefixed and trailing-slash spellings
normalize back to identical bytes via `pathlib`, while absolute or
`..`-containing spellings do not. **Behavior identity** — exit code,
violation count and order, section labels, semantic message — is invariant
across every shape. Consequently the 3-field tuple is a byte receipt for one
pinned invocation shape: B1/B2/R14 and this census all pin the canonical
relative form, so their receipts are mutually comparable; a future batch using
absolute paths would show byte mismatches for these 5 fixtures although
behavior is identical. This confirms and quantifies H3's finding #2. The
`exit 2` cases are argparse misuse only and are expected negative controls,
not passing results.

## Findings, severity-ranked

1. **Low — path-shape sensitivity is real but bounded to 5 fixtures.** Byte
   receipts for the 5 fixtures above (and any missing-directory probe) are
   reproducible only if the argv spelling is pinned; behavior is stable
   everywhere. No current receipt is affected (all use the canonical shape and
   all re-derived identically). Named risk for future receipt batches, not a
   defect in the delivered evidence.
2. **Info — B1 vs R14 row-count reconciliation, no drift.** B1's 166 rows are
   a correct census of its declared baseline `87779a0` (verified: 166 dirs);
   R14 measured 167 at `65838f8` (verified: 167 dirs). The single set
   difference is the r93 fixture added by the work commit — expected scope
   difference, not evidence drift, and not a reason to call either receipt
   wrong.
3. **Info — fixture tree id moved while checker-visible bytes did not.** A
   naive directory-tree pin across `65838f8`→HEAD false-flags (tree ids differ)
   although all 830 JSON blobs and the checker blob are identical; the right
   pin is per-blob. Recorded in `F02-pins.json` so future rounds do not
   misread the tree-id change as content drift.

No harm found on any axis by this seat. One harness note for honesty: the
first census attempt raised a `KeyError` in its sample-rerun block **before**
writing any evidence (bare names vs repo-relative keys); it was corrected and
the census re-run, so no partial or stale evidence file exists. The first
`F02-pins.json` draft contained a list-ordering artifact in a JSON-only
manifest comparison; it was diagnosed (830/830 files byte-equal, set-equal)
and the final file (sha `6f20b80a…`) records the corrected values.
