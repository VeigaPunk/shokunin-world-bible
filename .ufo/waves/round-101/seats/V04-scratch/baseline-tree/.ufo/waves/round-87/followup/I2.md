## The C1 after-state, stated exactly

Delivered code (`corpus/fixtures/check_bible.py:186-195,213,229-230,240-241,242-250`):

1. `holder_ambiguity_stop` is set at the FIRST ambiguous-holder record and
   carries `(origin_label, tuple_of_(field, id)_pairs)`.
2. At that stop record: the original item-level notice (`:243`) **plus** a
   per-record disclosure (`:250`). Both lines carry the same `record_label`.
3. At every later record of the item: the loop-top branch (`:189-195`)
   emits the per-record disclosure before any record validation.
4. The disclosure names the ORIGIN cause on every later record, never the
   later record's own holder state.
5. No chain-break or tick-order comparison finding is produced for the stop
   record or any later record of the item (the gate stays latched).

Verbatim disclosure text:

```text
{record_label}: provenance continuity and tick-order comparisons unassessed because ambiguous holder identity {field} {id!r} first occurred at {origin_label}
```

with several references joined by `, ` in the order `to_holder` then
`from_holder` (`:246-249`).
