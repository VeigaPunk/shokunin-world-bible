1. **Low, informational — `anchor_range_control.delivered_line_count: 220` is the synthetic control's length, not the checker's.** `run_anchor_range_control` builds `b"control line\n" * 220` (source line 555) so the out-of-range case (`:221-224`) is constructible; the real delivered checker is 428 lines, so that specific range cannot be out-of-range live. The live default run still exercises a real delivered-checker resolution (`:184` within 428) and a real legacy-baseline resolution (`:212-224` within 330). No document claims 220 = delivered length, but the unqualified field name invites that misreading. Mitigation: note only (read-only seat); the parent may prefer a `control_` prefix in a future repair round.
2. **Low, informational — `wrong_bare_anchor` is caught by the document digest, not by anchor parsing.** Changing `:322`→`:325` yields `document_drift` and the anchor-range check never runs (pins fail first, by design). R01.md states this bound; the case name is less precise than the behavior. Verified by adversarial probe 8 (second bullet).
3. **Informational — usage errors map to `failed`.** An invalid flag exits 1, the same class a red certification uses; stdout/stderr distinguish them. Within the declared map, no undeclared code.
4. **Informational — environmental dependencies.** The self-test needs `git` plus the pinned revision objects; absent them it fails loudly ("SELF-TEST FAIL committed inputs"), which I could not exercise here because the objects exist. `python3` on PATH is likewise assumed by the default run's `sys.executable` replay.

No high or medium finding: the previously audited false-certification defects (CB-audit: unchanged checker accepted, wrong in-range anchor accepted, injected contradictions accepted — all against the patch-only CERT candidate) are closed in the delivered committed gate by the checker digest (with execution prevented, probe 8), the document digest (fail-closed), and the committed adversarial self-test expectations.
