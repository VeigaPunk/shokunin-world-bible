1. **"20-case set" terminology (mission-vs-artifact mismatch, resolved).**
   The cert tool's replay set is **14** cases (doc line 41: "All fourteen
   pasted case blocks below replay"; observed `replay_cases=14/14`). The
   20-case set is the r10-era recorded run
   `corpus/live/runs/20261012T173416Z/`. Both verified. Future seats should
   not conflate the two.
2. **`r5-missing-file` byte identity is argv-shape-dependent.** Its violation
   line embeds `argv[2]` verbatim
   (`Errno 2] No such file or directory: '<argv-path>/contradictions.json'`).
   Replayed from repo-root paths it differs by the path prefix only; with the
   historical `.shokunin/lore/...` shape it is byte-identical. Behavioral
   identity holds everywhere (rc=1, same violation count); byte-identity
   receipts for this case must pin the invocation path.
3. **The discriminate harness's `README_exact` gate is output-visible only.**
   An output-invisible fixture mutation (display-name suffix on
   `r91-c1-null-chain/entities.json`) leaves `DISCRIMINATION HELD` exit 0.
   That is by design (it is a semantics discriminator, not a fixture
   integrity check), but the **checker-hash pin is load-bearing**: a single
   byte flip (`CLEAN:`→`XLEAN:`) leaves both fixture receipts byte-identical
   (violation outputs print no `CLEAN:` line) and only the pin catches it —
   in both the harness (exit 2 `checker-hash`) and the cert tool (exit 1
   pin FAIL). Do not weaken the pin.
4. **Carried (not re-examined):** AST anchor validation in
   `boundary_doc_check.py` remains the r94 debt named by C1/Q1
   (CB-audit showed any in-range citation resolves, e.g. `check_bible.py:1-2`).
   My probes cover the pin/C9/replay/structure gates, not anchor semantics.
5. **support_check exit contract:** `RESULT FAIL` exits 1 (observed on the
   anchor fire); `RESULT PASS` exits 0. Not documented in the cluster README;
   harmless, noted for future harness authors.
