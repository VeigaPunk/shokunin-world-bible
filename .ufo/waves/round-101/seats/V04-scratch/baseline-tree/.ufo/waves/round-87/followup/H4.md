## Strict additions-only verification

Script `/tmp/r87-H4/verify.py` (mechanically, not by eye) checks, per probe:

- every baseline `VIOLATION:` line survives **byte-identical** and in the same relative
  order (subsequence test over the after-run finding list);
- the multiset difference (after minus before) contains **only** lines matching
  `^VIOLATION: entities\[\d+\]\.provenance\[\d+\]: provenance continuity and tick-order
  comparisons unassessed because ambiguous holder identity <cause> first occurred at
  <origin>$`;
- no removed or altered finding;
- the non-`VIOLATION` footer count delta equals the number of added findings;
- stderr empty in both runs; exit code unchanged.

Observed (all five probes):

```text
r85-control:              0->0  preserved=True added=0 removed=[] footer_ok=True stderr_empty=True exit=0->0
r85-harbor-repro:         5->7  preserved=True added=2 removed=[] footer_ok=True stderr_empty=True exit=1->1
r85-isolated-ambiguous:   3->4  preserved=True added=1 removed=[] footer_ok=True stderr_empty=True exit=1->1
r85-masked-ambiguous:     3->5  preserved=True added=2 removed=[] footer_ok=True stderr_empty=True exit=1->1
r85-unique-break-control: 1->1  preserved=True added=0 removed=[] footer_ok=True stderr_empty=True exit=1->1
```

The two controls (`r85-control`, `r85-unique-break-control`) are byte-identical between
revisions — stdout, stderr and exit code all unchanged.

The exit-code invariance is also structural, not just observed: the new disclosure is
emitted only once `holder_ambiguity_stop` is set, and that latch is set only on a branch
that already appended an ambiguity `VIOLATION` (`corpus/fixtures/check_bible.py:226-246`).
A run that fires the new line therefore already exits 1; the change cannot flip an exit
code in either direction.

## New finding — the stored r85 receipts are two checker generations stale

The archived `corpus/live/runs/round-85/probe-r85-*.txt` receipts do **not** reproduce at
`28706dc`. Replaying the three checkers in lineage against the same inputs:

```text
probe                      r85-era d44a4e3 (88c9b1d0)   28706dc (e8f24162)   2b48ca7 (3ae4134d)
r85-control                matches receipt (0)          matches (0)          matches (0)

r85-isolated-ambiguous     matches receipt (1, 1 find)   1->3 finds          3->4 finds
r85-masked-ambiguous       matches receipt (1, 1 find)   1->3 finds          3->5 finds
```

The r85-era checker (`88c9b1d0…`, blob from `d44a4e3`) reproduces every stored receipt
exactly (body and exit code). The `28706dc` "harden check_bible" commit already added the
ambiguous-holder field finding and the global unassessed notice to these three probes; C1
then added the per-record disclosures. So:

- **Against the assigned baseline `28706dc`, the delta is additions-only, as claimed.**
- **Against the stored r85 receipts, the delta is larger and is not attributable to C1** —
  anyone diffing the delivered tree against `probe-r85-*.txt` will see 28706dc's hardening
  too. This is a pre-existing documentation gap (the r85 receipts are labelled with an
  earlier checker hash than the pinned baseline), not a C1 harm. Worth one line in the
  round record so the receipts are not read as the C1 before-state.

## Observations (not harms, no measured axis affected)

1. **The stop record gets two unassessed lines.** At the record where the latch is set, the
   pre-existing global notice and the new causal disclosure are both emitted (masked `[1]`,
   harbor `[1]`, isolated `[2]`). Both are true and the pre-existing line is preserved, but
   the new line is informationally partly redundant at that record. This is the same X1
   behavior the wave's R1 seat ranked below X3 (`R1.md:51`); it changes no exit code, no
   finding removal, and no clean case, so it is a wording/documentation note for C2/I2, not a
   measured harm.
2. **This replay is the independent pre-C1 witness for the changed path.** H2's §7.3
   coverage observation is that inside `corpus/fixtures/` the disclosure path is witnessed
   only by fixtures authored in the same commit as the code. The five r85 probe inputs are
   pre-existing inputs (authored in round 85, pinned by digest in `manifest.txt`) that do
   exercise the path; they are live-run telemetry rather than `corpus/fixtures/` fixtures, so
   they close H2's coverage gap only outside the fixture corpus.
3. **The isolated probe's added line is on a terminal record.** `r85-isolated-ambiguous`
   gains one finding at `provenance[2]` with no later record to disclose for; the line still
   adds the field/holder/origin detail the global notice lacks, so it is not wrong — it is
   the "no downstream record" case the C2 decision table should classify explicitly.

## Verdict

- **Additions-only on the three changed live probes — verified.** Zero removed, zero altered
  findings; all added lines are the documented per-record disclosure; footers shift by exactly
  the added count; stdout ordering of old lines preserved.
- **Exit codes unchanged — verified** for all five probes (`0,1,1,1,1` both revisions) and
  structurally impossible to change for the disclosure path.
- **Harm to the two controls and to all 133 pre-existing fixtures — none detected** (byte
  identical).
- **Harm to the three affected probes — none detected**; the only new content is a true
  statement about an ambiguity that was already being reported, plus the pre-existing
  masked-break silence, which C1 deliberately discloses rather than detects.
- **Caveat carried forward:** the stored r85 receipts are stale relative to `28706dc`; only
  the `28706dc → 2b48ca7` comparison supports the "only deltas are the disclosure lines"
  claim.
