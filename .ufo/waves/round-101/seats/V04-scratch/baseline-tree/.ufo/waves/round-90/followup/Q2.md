### M2 — poll-cap discipline

```sh
python3 - <<'PY'

for p in sorted(root.glob('*.md')):
    if p.name == 'wave-spec.md': continue
```

Observed (21 seats with a shell poll loop): `C5 C7 C8 D2 E1 E2 F1 K1 M1 M2 M4 Q1 S1 S2 SE1 SE3 T1 W1 W2 X2 X3`
(+2 Python-loop seats: R1 `poll_result=20_minute_deadline`, B2 `deadline_reached=true`).

Cap-related defects, quoted verbatim from the seat reports:

| seat | defect | verbatim |
|---|---|---|
| C5 | terminal record lost | "The background runner reached its 1200-second timeout after these 20 checks." (`C5.md:26`) |
| J3 | 600 s cap + 420 s cap | "Its default 600-second tool cap ended it after the `06:01:01` check." … "its 420-second cap stopped it before a deadline/final line." … "This left a `4m54s` restart gap" (`J3.md:92`) |
| M3 | 600 s cap, gap | "the first 20-minute-loop process hit the tool's 600-second cap, and its report-path test logged literal `M1.md`/`M2.md` names as present" … "There was a 1m47 gap after the first process timed out" (`M3.md:19`) |
| D2 | 600 s default | "the poll was resumed in a second call after I noticed the initial background task's default 600-second timeout" … "leaving a 73-second interval between checks 07 and 08 and a 13-second-late final check" (`D2.md:9,450`) |
| Q1 | terminal record lost | "the task terminal status was `timed_out` at 1200 seconds (`exit_code=-1`), so there is no closing sample or deadline marker in the log" (`Q1.md:239`) |
| S2 | terminal record lost | "hit the 1,200-second tool timeout (`status=timed_out`, `exit_code=-1`) before emitting the planned `deadline-reached` line at 06:13:44" (`S2.md:133`) |
| W2 | terminal record lost | "timed out at its 1,200-second limit (`terminal_reason=timed_out`, `exit_code=-1`) before the scheduled check 21 or `poll_complete` marker" (`W2.md:194`) |
| SE1 | sampling gap | "the resumed loop therefore had an approximately seven-minute sampling gap" (`SE1.md:126`) |

So **8 of 21 polling seats recorded a cap-related defect; 5 of them lost the terminal in-loop record
by being killed at exactly the 1200 s boundary the loop was checking.** Root cause is arithmetic, not
luck: the loop's internal deadline equals the host timeout (1200 s explicit, 600 s default), there is
no margin and no `trap ... TERM` terminal line, so the protocol's own closing receipt is the first
thing the kill destroys. Clean terminal records exist where a seat printed on/before the boundary
(C7 "deadline inventory … elapsed=1200s", E2 `DEADLINE_REACHED`, M4 "deadline reached (1200s)", F1,
M2, M1, R1, B2) — the fix is cheap and demonstrated. r89 comparator: "10 seats hit the 600 s
foreground cap" (`LOG.md`, r89 closure). r90 therefore fixed the *shape* (one-call loops) but lost
the *receipt* (5 boundary kills) and still paid 3 default-cap restarts with 73 s–294 s blind gaps.

## Findings & named debt

- **F1 (no blocking finding).** Freeze-then-verify PASS: `ff9fd2aa…` both sides; the C9 integer-only
  ruling is what the delivered tree contains. C2's delivered support command reproduces `22/22`,
  `10/10`, paraphrase retelling-only, exit 0 — M5's span fix is the shipped revision.
- **F2 — seat accounting is still prose (R90-P1, carried from Q89-040 / r88-I3).** declared 32 /
  enumerated 29 / delivered 33; the spec header *claims* "roster-as-data per r88 Q2-I3" while being a
  Markdown file — a compliance claim without a mechanism, repeated from r89's spec line 1. Debt:
  unreconciled count fields + unenumerated supplementary seats.
- **F3 — the cutoff is structurally biased (R90-P2).** 0/12 dependent seats and 17/17 author seats
  landed inside the 20-minute window; the supplementary batch has now carried the round's decisive
  verification twice (r88 6 seats, r90 4 seats). The landing record is written before the seats that
  verify the round exist — W1's manifest covers 17/29, and SE3 (a later sentinel) still could not see
  M5/C9/W3 reports.
- **F4 — the poll protocol loses its own closing receipt (R90-P3).** 8/21 polling seats recorded a
  cap defect; 5 lost the terminal in-loop line by being killed at exactly their own 1200 s deadline;
  3 paid 600 s-default restarts with 73 s / 1m47 s / 4m54 s blind windows. r89's 10×600 s losses
  became r90's 5×1200 s receipts lost + 3 restarts: shape improved, evidence did not.
- **F5 — inode ceiling is a standing systemic risk (R90-P4).** `/tmp` sat at 0 free inodes; one seat
  was blocked from scratch entirely; 20 r90 residue entries (2,137 files) remain unswept while the
  same round demonstrated the low-inode pattern in 3 seats. No pre-flight check, no declared budget,
  no closure sweep exists.
- **F6 — rulings need an artifact, not only a ruling (R90-P5).** The C9 ruling changed the delivered
  bytes by composing two losing alternatives; that composition has no seat-owned artifact and no
  hash-stamped freeze, so under r88-I1 it is exactly the "integrator amendment" class the freeze
  discipline exists to catch. It was disclosed (amendment + commit body) and it verified — but the
  first byte-level check had to be a phase-2 seat.
- Non-findings recorded to avoid over-claiming: all 24 patches are seat-prefixed (attribution clean);
  the ruling quotes its superseded text (auditable); the two Python-loop polls (R1, B2) both emitted
  clean terminal markers — the defect is specifically in hand-rolled `sleep 60` shell loops with
  `deadline == timeout`.

### 3 improvements for r91 (each measurable)

- **P1 — one canonical, committed poll helper with a margin and a TERM trap.** Commit
  `corpus/tools/poll.sh` (or `.ufo/waves/round-91/poll.sh`): args = deadline seconds, artifact
  predicates (no glob matching — `-f`/`find -maxdepth`), heartbeat per check; internal deadline =
  requested − 120 s; `trap 'emit TERMINAL reason=signal; exit 124' TERM`; document
  `timeout = deadline + 180 s` for the host call. Ban hand-rolled loops for dependent seats.
  *Verification:* `grep -c 'poll.sh' .ufo/waves/round-91/*.md` ≥ number of dependent seats, and zero
  seats reporting `timed_out` without a `TERMINAL` line. *Target:* 0 lost terminal records (from 5),
  0 mid-window restarts (from 3).
- **P2 — publish the roster as data and close the supplementary window before the manifest.**
  `wave-spec.json` with `seats[] {id, phase, claim, role(author|verifier|clerk), lane_requested}`,
  `amendments[] {id, supersedes(text), ruling, shipped_artifact_sha256}`, and a committed validator
  that fails when `declared != enumerated != delivered`, when any delivered artifact lacks a seat
  prefix, or when an amendment names a ruling but no composed artifact hash.
  *Verification:* `python3 corpus/tools/wave_validate.py .ufo/waves/round-91` exits 0;
  r90's own data would exit non-zero (32/29/33, composition without artifact) — run it on r90 as the
  negative control. *Target:* 0 unexplained count deltas; any ruling that changes delivered bytes
  ships as one hash-stamped patch.
- **P3 — scratch budget, pre-flight, and a closure sweep with a freed-inode receipt.** Declare
  `SCRATCH_BUDGET` (one `mktemp -d` per seat, path-limited `git archive`, `trap rm -rf EXIT`,
  ≤200 files); pre-flight `df -i` with a named fallback root when free inodes < 5% (W2's block must
  be impossible); the clerk/sentinel runs a round-scoped sweep (`rm -rf /tmp/lore-r91-*`) and records
  freed inodes. *Verification:* `df -i /tmp` before/after + `ls -d /tmp/lore-r91* | wc -l` → 0.
  *Target:* 0 blocked seats (from 1), 0 round residue (from 20 entries / 2,137 files).
