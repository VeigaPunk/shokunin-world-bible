## 2. No false missing / duplicate / phantom findings

Five independent lines of evidence, all pointing the same way.

**a. No finding line was emitted at all.** `emit()` prints one `FINDING <id>: <detail>` line per finding before the `RESULT` line (`corpus/tools/map_obligations.py:63-66`). The r93 run above produced only the two lines `OBLIGATIONS ...` and `RESULT PASS` — zero `FINDING` lines. Since `compare()` is the sole source of findings and is exhaustive over both directions of the one-to-one relation (`corpus/tools/map_obligations.py:305-321`: `duplicate_mapping` and `phantom_obligation`/`source_id_mismatch` for every mapped pointer, then `missing_obligation` for every raw pointer), a clean emit means all four finding classes are empty.

**b. Independent recount of the raw side agrees.** Read directly from the JSON, not from the tool:

```
$ python3 -c "...json.load of entities/relations/timeline..."
entities: 4 relations: 2 timeline: 2
first_appearance keys: 4 entity claims: 4
INDEPENDENT_RAW_TOTAL = 12
```

4 `first_appearance` + 4 entity claims + 2 relations + 2 timeline = **12**, matching `raw=12`.

**c. Independent recount of the map side agrees.** The `## JSON facts` table holds exactly 12 pointer rows, matching `mapped=12`; the map header self-declares the same count (`corpus/fixtures/r93-m2-kojiki-cluster/claim-excerpt-map.md:16`: `## JSON facts (12 source-attributed pointers)`). Row IDs run E1–E12 with no gaps or repeats.

**d. The detectors are live on *this* fixture, so the PASS is not vacuous.** Four mutations were applied to isolated copies under `/tmp` (the repo was never modified); each was caught with the correct stable finding ID and exit 1:

| Mutation on a /tmp copy | Observed stdout | Exit |
|---|---|---|
| delete the `E12` row | `OBLIGATIONS raw=12 mapped=11` / `FINDING missing_obligation: timeline.json#/1 has no map row` / `RESULT FAIL` | 1 |
| repeat the `E1` row | `OBLIGATIONS raw=12 mapped=13` / `FINDING duplicate_mapping: entities.json#/0/first_appearance appears 2 times` / `RESULT FAIL` | 1 |
| repoint `E12` to `timeline.json#/9` | `FINDING missing_obligation: timeline.json#/1 has no map row` + `FINDING phantom_obligation: timeline.json#/9 is not a raw source-attributed obligation` / `RESULT FAIL` | 1 |
| change `E9`'s in-world source ID to `m2-other-source` | `FINDING source_id_mismatch: relations.json#/0 does not bind to 'm2-record-archive'` / `RESULT FAIL` | 1 |

Because each mutation on the same map/data pair flips the verdict, the clean r93 result is a real absence of findings, not a tool that cannot produce them.

**e. The one real false-positive risk is correctly avoided.** The map carries 3 editorial comparison rows (`S1`–`S3`, `## Editorial rows (3 external comparisons; not JSON facts)`, `claim-excerpt-map.md:33-39`). A parser that swept the whole file would have raised 3 `phantom_obligation` findings. The parser instead scopes strictly to the single `## JSON facts` section and stops at the next heading (`map_obligations.py:184-194`), and the observed run counted 12 rows, not 15 — so the editorial rows contribute no findings, as designed.
