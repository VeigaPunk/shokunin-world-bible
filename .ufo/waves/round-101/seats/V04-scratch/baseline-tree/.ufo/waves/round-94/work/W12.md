## Bounded accepted grammar

A map fact row must contain exactly one backtick-delimited canonical pointer token. Other explanatory text in the row is not part of that token. Use canonical unescaped JSON Pointer syntax and canonical array indexes only:

```text
Index   ::= "0" | [1-9][0-9]*
Pointer ::= "entities.json#/" Index "/first_appearance"
          | "entities.json#/" Index "/claims/" Index
          | "relations.json#/" Index
          | "timeline.json#/" Index
```

A syntactically valid pointer must then resolve to an existing source-attributed raw obligation. Missing, duplicate, phantom/non-obligation, or source-ID-mismatched mappings are comparison failures (`RESULT FAIL`, exit 1), not grammar errors. Malformed raw JSON or a map row that cannot be parsed under this bounded grammar is could-not-evaluate (`RESULT ERROR`, exit 2). This does not certify support, entailment, delivery mode, or other R9 judgments.

## Negative grammar cases

Each case below must produce `RESULT ERROR` and exit 2, never PASS/empty inventory:

| Map-row content | Why rejected |
|---|---|
| `` `entities[0].first_appearance` `` | r88 bracket/dot syntax, not canonical pointer form |
| `entity zero first appearance` | prose-only reference has no pointer token |
| `` `entities.json#/0/first_appearance`; `entities.json#/0/claims/0` `` in one fact row | co-mapped row; grammar permits exactly one obligation per row |
| `` `entities.json#/0/claims~10` `` | escaped token is outside this literal, fixed-token grammar; do not silently decode/alias it |
| `` `entities.json#/../0/first_appearance` `` or `` `entities.json#/0/../first_appearance` `` | traversal-like path tokens do not match the allowed array-index/member sequence |
| `` `entities.json#/00/first_appearance` `` | non-canonical array index spelling |
| `` `contradictions.json#/0` `` | unsupported file family |

Recommend a stable finding ID such as `unsupported_pointer_grammar` for these inputs; that identifier is a design suggestion, not an observed tool output. A valid pointer duplicated on two separate rows is different: the rows parse, then duplicate mapping should be `RESULT FAIL` / exit 1 per the contract.
