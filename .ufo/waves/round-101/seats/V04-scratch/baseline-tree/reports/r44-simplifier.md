# Round 44 simplifier — no-go on ontology guard

## Decision
**No-go for checker/fixture changes on the present evidence.** The proposed “timeline actor must be a character” premise is not an established schema convention. `timeline.entity_id` is explicitly a generic entity reference, and entity kinds include character, place, faction, and item (`corpus/fixtures/check_bible.py:7-13`). The checker validates reference presence and duplicate-ID ambiguity, then uses that generic ID in occupancy; it does not validate actor kind (`check_bible.py:228-252`). A unique place used as `entity_id` could therefore evade a character-only expectation, but a CLEAN result would establish only that the schema/checker permit it—not that the record is semantically invalid.

## Evidence and precedent
- LOG’s own declaration correctly marks the character-only claim as an assumption and warns that places/factions/items may properly be timeline subjects (`LOG.md:738-739`). The candidate scope “character-location event” lacks a demonstrated schema discriminator or established restriction.
- README characterizes the existing occupancy rule as “A character cannot occupy different places at the same tick” (`corpus/fixtures/README.md:256-265`), but nearby identity caveats state ID resolution does not establish real actor identity. That describes the current rule, not an exhaustive ontology contract.
- R11 tests `place_id` kind (place-v-character and unique-nonplace controls), not `entity_id` kind; README explicitly says those tests do not change actor identity or occupancy rules (`README.md:235-241`). Thus they do not establish the proposed actor restriction.
- R12 compares unique versus duplicate actor IDs for occupancy certainty, and documents no character-kind verification (`README.md:243-265`). R13 further says ID counts are not independently proven character identity; a string kind outside allowed kinds still counts and is separately flagged (`README.md:279-287`). These precedents favor reference/identity diagnostics, not a newly inferred character-only constraint.
- R21 paired clean/reverse/malformed, wrong-kind-place, and ambiguous-actor fixtures cover place validation and event-structure handling, not a non-character actor convention. `r21-wrong-kind-place/timeline.json` changes place resolution, while its actor remains `mira`; this cannot support an actor-kind rule.

## Smallest defensible next step
Do not add a guard or fixture merely to demonstrate a type the current contract does not prohibit. If the project owner establishes an explicit contract that a particular timeline-event class requires a character actor, then the narrowest future experiment is a one-field mutation of a clean control: switch only that event’s `entity_id` to a unique place while keeping all references/citations valid; retain a character control. Limit any diagnostic to that explicitly specified event class, not all timeline rows.

## Falsifiable gate
**Go** only if an existing authoritative schema/document convention (or owner-approved event-class contract) explicitly requires character actors for the targeted rows, and a controlled valid-input pair shows the checker currently accepts the forbidden unique-place actor while the character control remains clean. **No-go** if no such convention exists, if the claim depends only on the field name `actor` in diagnostics/README prose, or if a guard must apply to all generic `entity_id` rows. Falsifier: one supported timeline event with a non-character subject under the established contract invalidates an unconditional guard; absent a scoped contract, do not implement.

## Risks / limits
An unconditional `kind == character` check invents ontology and can reject valid place-, faction-, or item-centered events (calibration harm). A diagnostic based on the occupancy rule risks conflating its current character-oriented prose with universal schema validation. Conversely, leaving the generic reference unchecked for kind may admit records users consider malformed, but that is a contract question, not inferable from these fixtures. IDs, citations, and checker output prove neither actor ontology nor source truth/canon.
