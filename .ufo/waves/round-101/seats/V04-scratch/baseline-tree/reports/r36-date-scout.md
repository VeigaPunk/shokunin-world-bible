# Round 36 date scout — shared-ringing calibration

## Assessment

The controlled near-miss is useful and well-targeted: r35's narrow positive depends on the two reports identifying the same occasion, and a differing explicit date removes that support even if every structured reference remains valid. This tests whether a reviewer follows the source-text dates rather than treating Bell-7 labels, matching ticks, or a clean checker result as proof of shared occasion. It does not establish a positive contradiction; the proper result is “same occasion not established,” not “accounts false” or “Sella was at Harbor.”

## Evidence

- Round 35's initial reviewer failed the “day of this note” wording because separately authored notes could name different days; the remediation explicitly supplied the seventh day of Embermonth, year 12 and the sole seventh-watch ringing (`.shokunin/lore/LOG.md:562,565,569`). The final adjudicator admitted only a conditional incompatibility between attributed reports, contingent on person/place/occasion alignment (`.shokunin/lore/LOG.md:570-571`; `.shokunin/lore/reports/r35-axis-adjudicator.md`, “Shared occasion” and “Per-axis judgment”).
- Tarin's prose names the seventh day and sole Bell-7 ringing (`.shokunin/lore/corpus/fixtures/r35-bell7-conflict/tarin-note-excerpt.md:1-3`). Sella's corresponding prose says “that same Bell-7” and independently names the same seventh-day date (`.shokunin/lore/corpus/fixtures/r35-bell7-conflict/sella-bell7-note-excerpt.md:1-3`). This match—not the label alone—is the material occasion support in r35.
- The JSON deliberately encodes the r35 date in the inherited Sella claim and Tarin event description, and in Sella's timeline event (`.../entities.json:1`, `.../timeline.json:3-4`; inspect the Sella/Tarin rows). The ledger rationale also presumes both reports concern the sole Bell-7 on that seventh date (`.../contradictions.json:1`). The map explicitly says date/uniqueness are fictional claims, tick 3 is not date evidence, Tarin's Harbor field is observation scene, and checker checks structure only (`.../manual-clause-pointer-map.md:3,9-17,19-21`).
- The Round 36 declaration specifies preserving all five JSON tables byte-for-byte and changing only Sella's excerpt date to day eight; it anticipates the important prose/structured-event and ledger-rationale mismatch and says the near-miss must not be read as same-occasion conflict (`.shokunin/lore/LOG.md:573-576`). This creates a particularly clean calibration probe: JSON still narrates the old same-date version, while Sella's new cited source text does not.

## Risks / interpretation limits

1. A reviewer could over-weight the unchanged event description or ledger `why` as if they independently proved Sella's eighth-day report occurred on the seventh. They are structured records derived from the earlier text, not new corroboration; with sole excerpt change they are stale relative to the source prose. Explicitly flag this discrepancy rather than silently harmonizing either representation.
2. “Bell-7” is reused as a label across dates. Shared label and tick 3 do not imply one occurrence; r35 itself required exact date plus sole-ringing assertion. Even that is only fictional source testimony, not authenticated chronology.
3. The differing dates defeat the *shared-occasion premise* for this pair; they do not disprove the underlying accounts, prove either note's date false, or establish Sella's location on the seventh day. The claim is about evidentiary insufficiency, not logical impossibility across all possible narratives.
4. A clean checker result would only show JSON shape/references. It cannot validate excerpt contents, source-text/JSON agreement, date semantics, truth, or canon; the pointer asymmetry remains (Tarin's Harbor scene versus Sella's reported Tower location).

## Falsifiable check

Compare the r35 and proposed r36 artifacts. Confirm all five r35 JSON files are byte-identical; confirm the sole source-text edit is Sella's explicit date changing from seventh to eighth day, while Tarin remains seventh; and confirm Sella's event/ledger still cite the unchanged structural rows. Ask an independent reviewer, without prompting the answer, whether the cited excerpts establish one common Bell-7 occasion. **Expected calibration result:** reviewer declines to treat them as a same-ringing conflict and identifies the conflicting date / stale structured rationale. The claim is falsified if the reviewer can point to source text that unambiguously dates Sella's report to the seventh-day ringing despite the eighth-day statement, or if the purported control changes other source wording/JSON and therefore no longer isolates date. A checker exit 0 is not a pass for this semantic check.
