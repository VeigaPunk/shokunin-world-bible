# Round 44 regression scout — pinned replay and ontology gate

## Scope and verdict

**No-go on implementation as currently framed.** The generic `entity_id` field and available precedents do not establish a character-only actor ontology. In particular, Round 11 tests a non-place *place_id*, not a non-character *entity_id*. The proposed `harbor` substitution is a useful falsification probe, but CLEAN/non-CLEAN on that invented input cannot by itself justify a universal actor-kind restriction. Require an explicit, existing convention that timeline actors are characters (or limit the rule to a demonstrated character-location event subset) before any checker change. Preserve the proposed control/replay plan for a later authorized experiment.

## Ontology evidence and counterevidence

- Checker schema types timeline `entity_id` and `place_id` both as strings, with no actor-kind condition in schema (`.shokunin/lore/corpus/fixtures/check_bible.py:12`). Timeline validation resolves/detects dangling IDs for both fields; it reports an ambiguous actor but does not inspect the uniquely resolved actor's kind (`check_bible.py:228-242`). Occupancy keys by raw `entity_id` plus tick, gated on unique actor ID, valid unique place-kind `place_id`, and nonnegative tick (`check_bible.py:245-252`). This supports a real asymmetry in checker validation, but not the intended ontology.
- README states “A character cannot occupy different places at the same tick” (`.shokunin/lore/corpus/fixtures/README.md:21-22`). This grounds the *occupancy rule* in characters. It does not state that all timeline `entity_id` values must be characters, nor that all events are occupancy assertions.
- Round 11's paired same-ID tests explicitly vary entity row order for place-vs-character resolution and separately test `place_id` wrong-kind behavior (`README.md:218-241`). It expressly excludes actor identity/occupancy from that round (`README.md:241`). It supplies no non-character actor test.
- Round 12 establishes definite same-actor occupancy only for uniquely indexed `mira` and suppresses inference for ambiguous actor IDs; it calls this identity ambiguity, not kind validation (`README.md:243-261`). Its examples use character Mira, but examples do not establish an exclusive type rule.
- Round 21 protects occupancy's independent certainty guards when `depends_on` is malformed and lists wrong-kind-place/ambiguous-actor controls (`README.md:443-460`). It does not test a uniquely indexed non-character actor. Its focus is dependency-member recovery.
- Corpus contains many fictional relations/events about factions, items and records; the fixture README explicitly says holder IDs are entity IDs and kind need not mean legal ownership (`README.md:137-139`). This does not prove those kinds may be timeline actors, but makes an unqualified “entity means character” inference unsafe. A place, faction, item, or institution could plausibly be the subject of an event; this is an ontology risk, not evidence that any current fixture uses it.

## Risks / decision test

**Go** only if cited repository convention or an explicitly scoped event ontology demonstrates this field must denote a character for the proposed cases; the pair reproduces the existing behavior and the narrow guard rejects only the forbidden actor; exact pinned replay passes; and independent review finds no valid non-character actor class suppressed. **No-go** if the only support is the occupancy sentence, Mira-only examples, generic `entity_id` wording, or the newly invented probe itself; if other event kinds may legitimately use non-character actors; if replay differs; or if the guard changes unrelated diagnostics. If no convention exists, resolve ontology/editorial scope first and retain current checker behavior. No implementation or fixture change is authorized by this report.
