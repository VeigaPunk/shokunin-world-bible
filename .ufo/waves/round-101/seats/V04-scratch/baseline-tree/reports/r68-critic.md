# Round 68 critic — strongest NO-GO case

## Verdict: NO-GO on material calibration gain (provisional)

The declaration identifies a plausible classification distinction, but the claimed user-facing improvement is not yet demonstrated. The strongest counterargument is that a blank dependency string already receives a direct, field-located diagnostic: the existing code treats it as an ordinary string, looks it up, and emits `timeline[i].depends_on: unknown event ''` (or the quoted whitespace value). That statement is literally true of the supplied event-ID index. Replacing or supplementing it with “required nonempty string” may improve taxonomy, but does not yet establish a materially more actionable repair: the author still must choose the intended event ID, which neither diagnostic can infer. The declared matched controls establish changed wording, not that the prior diagnosis misled a user or blocked repair.

## Concrete source observations

- `.shokunin/lore/corpus/fixtures/check_bible.py`, `FIELDS['timeline']['depends_on']`, requires a list but does not validate its members for nonemptiness. In dependency traversal, `if not all(isinstance(dep, str) ...)` only rejects non-string members; `''` and whitespace pass. Each first-seen string then reaches `event_id_counts.get(dep, 0)`, whose zero branch emits `unknown event {dep!r}`. Thus baseline blank-string output is not silent, not a crash, and not a false positive about a matching event ID in the admitted timeline index. The declared proposed diagnosis is more structural, but overlaps the existing repair signal.
- Existing neighboring policy is mixed rather than a clean precedent: required string fields in `FIELDS` reject `.strip()`-blank values during row admission, while dependency members are only checked for Python string type. The round can reasonably make that policy consistent, but consistency alone is not evidence of material calibration improvement.
- `.shokunin/lore/reports/r20-dependency-scout.md` and round-20 fixtures document dependency membership, unknown/ambiguous IDs, and inversion as separate input checks; they do not show that an empty ID was mistaken for a valid event or for a source/canon claim. `.shokunin/lore/reports/r22-schema-scout.md` and `.shokunin/lore/reports/r22-critic.md` concern non-string members that mask *all* sibling checks (including valid string edges). Recovering those siblings has a distinct functional effect. Empty strings do not trigger that early skip, so round 22 is not evidence that the r68 change is similarly material. The corresponding controls are `r22-malformed-only`, `r22-mixed-first`, and `r22-mixed-last` under `.shokunin/lore/corpus/fixtures/`.
- The declared scope is calibration only. No source text, fictional-world fact, event occurrence, chronology, or canon is established by either diagnostic. A more precise label for malformed input may count as taxonomy refinement, but it must not be promoted to a demonstrated improvement in event-membership accuracy: for blank `dep`, the membership result remains zero either way.

## Falsification / admission challenge

The declaration's criterion says the move is falsified if prior behavior already identifies the structural defect or the reviewer finds no material distinction. Here the old message already points to the exact dependency field and prints the offending empty value while stating that it has no indexed event match. That gives a credible NO-GO: no distinct edge, event, or valid dependency is newly surfaced, unlike r22; the proposed rule changes how the same malformed value is described. In addition, `depends_on: []` is valid (`r20-valid-order`), so the new nonempty constraint must remain per-member and must not imply that a dependency list itself must contain an ID.

If the proposal emits both “required nonempty” and “unknown event” for the same blank member, it may add noise without adding a repair path. If it suppresses the unknown finding, it removes a true index-membership observation; that may be a sound presentation choice, but should be stated as diagnostic replacement, not as discovering previously hidden absence. Whitespace-only values have the same issue after `.strip()`: exact index membership is false, while the structural diagnosis adds no intended ID. Repeated blank members also need an explicit policy: today the first gets unknown and later occurrences get repeated-reference findings; a new guard could alter those signals. These are candidate risks, not claims that an implementation has made them.
