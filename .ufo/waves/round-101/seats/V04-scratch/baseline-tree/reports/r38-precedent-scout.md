## Risks and falsifiable check

A tempting but wrong interpretation is that the duplicate row chooses which Sella note is canonical, or that it makes Sella’s reported account false. It does neither: row multiplicity makes a citation identity ambiguous, not source-text truth, authenticity, or canon. Likewise the ledger `why` is editorially conditional and does not convert the checker into a semantic contradiction adjudicator (`.shokunin/lore/corpus/fixtures/r35-bell7-conflict/contradictions.json:12`). A duplicate may also generate ambiguity diagnostics at other references to the same ID; report the complete output, not just the ledger line. The checker’s index dictionary is last-wins internally, but the count/status path is what guards this ledger source check (`check_bible.py:45-56,64-74,92-100`); avoid implying it selected a winner.

Falsifiable coverage check: compare a clean r35-derived control against a negative differing only by one additional structurally admitted `sources.json` row duplicating `sella-bell7-note`. Control must exit 0. Negative must preserve unique event IDs and report both the duplicate source ID and `contradictions[0].claim_b.source_id: ambiguous in-world source 'sella-bell7-note'`; enumerate every other ambiguity finding. If claim_b is not diagnosed, an event pointer is nonunique, or additional unaccounted changes/diagnostics appear, the narrow claim fails or must be revised. This establishes input/reference ambiguity coverage only, not truth, canon, authenticity, rights, or semantic contradiction.
