# Round 61 executor — source-index availability

## Candidate and policy

Implemented a narrow source-table availability state in `corpus/fixtures/check_bible.py`. Availability is true only after successful JSON decoding of a top-level array, including `[]` and arrays whose malformed rows are later rejected. Missing/read/Unicode/JSON/duplicate-member and non-array input remain unavailable with their existing direct diagnostic. `source_status` returns `unavailable` rather than `unknown`/`unique`/`ambiguous`; direct citation reporting consequently emits no membership conclusion. The ledger's no-resolvable-source branch only applies to loaded arrays. Provenance citations stay unassessable and chain checks are not treated as sourced when index unavailable, while record shape, holder references, and tick checks continue. Allied reciprocity is not asserted missing solely due to unavailable source index. Loaded-array logic is otherwise unchanged.

## Costs and boundary

Suppression loses per-reference repair pointers while the index is unavailable; the retained file/shape diagnostic identifies the table to repair, then rerunning restores row locations. A loaded array with rejected rows still counts as available over admitted rows, and a citation found only in a rejected row may remain unknown; this preserves existing row-filter behavior. No CLEAN/resolved/source-text conclusion is inferred. These are input-ID-index diagnostics, not claims about fictional-world absence, textual support, truth, chronology, canon, ownership, license, rights, or permission.
