## Ways the proposed coverage test can pass falsely

1. **Unsourced reverse edge accepted as the symmetry witness.** The declaration says the reverse edge must be explicitly sourced. A checker that tests only whether reversed endpoints and type occur will accept a reverse row with an unknown `source_id`. Existing `source()` reports that citation error separately, so the whole fixture may exit 1, but it still falsely treats the symmetry condition as satisfied and may omit the relation-local missing-qualified-reciprocal violation. Require the witness's source ID to resolve in `sources.json`, or explicitly specify that source validity is an independent gate and test that behavior. Relevant code: `check_bible.py` `source()` and relation loop; `consistent/sources.json` shows the source index convention.

2. **Wrong endpoint kinds or duplicate entity IDs contaminate eligibility.** The existing checker verifies relation endpoints exist, but does not verify relation endpoints are factions; `index('entities')` also records duplicate IDs as an error and overwrites the earlier row. If the new pass treats any `allied_with` endpoints as factions, it broadens the declared rule; if it uses the overwritten entity index without testing/handling duplicate IDs, record order can change whether an edge is considered eligible. Keep non-faction `allied_with` outside this class as declared, and do not claim a reliable faction decision where an endpoint ID is duplicate/ambiguous. Evidence: `KINDS` includes `faction`, but relation loop only tests membership in `entities` (`check_bible.py`); entity index duplicate handling is in `index()`.

3. **Self-edge and duplicate-row false passes.** For `allied_with(A,A)`, endpoint reversal is identical to the original row, so a naïve `any(reverse)` predicate lets one record satisfy itself. Repeated copies of one self-edge also look like reciprocal evidence. The round-2 declaration does not say how self-alliance is treated. Exclude/report self-edges separately or define them explicitly; do not use self-edge as positive proof of a reciprocal pair. Rule scout report `.shokunin/lore/reports/r2-rule-scout.md` also flags this unresolved case.

4. **Fixture-only gain can overstate general coverage.** The proposed pair exercises only a valid two-faction, two-direction case versus one missing direction. It cannot establish behavior with unrelated relation types, wrong-kind endpoints, unknown-source reverse edges, self-links, duplicates, or multiple parallel edges. Existing `carries` is a useful regression guard, but a passing pair alone proves only this narrow predicate. The claim is intentionally narrow; document the limit rather than generalizing it to relation consistency.

## False negatives / semantic caution

A pair of invented edge records citing the same fictional treaty proves only that the checker recognizes a locally stipulated reciprocal-edge convention. It does not prove that alliance relations in the fictional canon are symmetric, that a one-way source is a contradiction, or that all missing reverse edges are errors. The LOG's caveat against inference from prose is appropriate. Keep the output phrased as a convention/check failure (not a canon truth claim), and ensure the fixture citations actually identify the asserted reciprocal edges; schema-valid source IDs alone do not demonstrate evidential independence or source agreement. Evidence: `.shokunin/lore/LOG.md` round-2 scope; `.shokunin/lore/corpus/fixtures/README.md` and source citation convention.

## Critic conclusion

Coverage gain remains **unproven at this inspection point** because the new checker pass and positive/negative fixtures are absent. If later added, the minimum evidence for the narrow declared claim is replay of baseline-consistent, reciprocal, and one-way cases plus an audit that an invalid/unknown-source reverse row is not treated as a valid witness. Avoid claiming more than the exact faction `allied_with` convention; the listed edge cases are not covered by a two-case fixture pair.
