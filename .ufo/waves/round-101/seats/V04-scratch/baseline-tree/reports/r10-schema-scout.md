# Round 10 schema scout — observed constraints and suggestions

## Observations (from checked-in files)

Inspected `.shokunin/lore/corpus/fixtures/check_bible.py`, `.shokunin/lore/corpus/fixtures/README.md`, and the clean baseline `.shokunin/lore/corpus/fixtures/consistent/{sources,entities,relations,timeline,contradictions}.json`.

- The checker reads five required JSON-array files: `sources.json`, `entities.json`, `relations.json`, `timeline.json`, and `contradictions.json` (`FIELDS` in `check_bible.py`). Every row must be an object with the listed required fields of exact Python types; strings must be nonblank. Extra keys are generally tolerated.
- Each source row needs `id`, `title`, `kind`, `reliability_note` strings. Referenced sources are resolvable only if the ID appears exactly once; unknown and duplicate IDs are reported at each use. The checker does not read or validate source-excerpt text.
- Entity rows require `id`, `kind`, `name`, `first_appearance`, and `claims`. `kind` must be one of `character`, `place`, `faction`, `item`. First appearance must resolve to a unique source. Each claim is checked as an object with nonblank string `statement` and string `source_id`, and that source must resolve uniquely. The claim checker does not validate exact keys or require the source-id string itself to be nonblank before resolution.
- Relation rows require string `from`, `to`, `type`, and `source_id`. Both endpoints must resolve through the entity ID index, and the source must be unique. No general relation-type vocabulary or endpoint-kind pairing is enforced. Special case: distinct faction-to-faction `allied_with` rows need a reciprocal edge with uniquely sourced citation.
- Timeline rows require string `id`, integer `tick` (booleans are rejected by exact-type schema check), string `entity_id`, `place_id`, `description`, `source_id`, and list `depends_on`. Entity and place IDs must resolve; `place_id` must identify a `place`; source must resolve uniquely; tick must be nonnegative. Dependencies must be strings, not self/repeated, resolve to exactly one event, and have strictly earlier ticks. Same entity/tick at differing places is flagged; same place is allowed. Event IDs must be unique to avoid duplicate-ID error and ambiguous dependency behavior.
- The baseline adds `mira` (character) and existing `harbor` (place), `departure` at tick 1 and `arrival` at tick 2; the two route events cite `courier-log`. This is the existing route, not a constraint to alter it.
- `.shokunin/lore/corpus/fixtures/README.md` says citations point to fictional in-world records and the checker validates pointers, not truth of prose. The `sources.json` descriptions likewise characterize sources as limited accounts. No prose excerpt field or excerpt-file convention is implemented in the checker/schema; round-10 excerpts therefore need a clearly identified separate authored artifact if the narrative claim is to be compared by a reader.

## Recommendations (not checker requirements)

- For a separate extension, keep all IDs unique and cite a unique source ID on each new entity's first appearance and each claim, relation, and event. Give every added entity at least one specific claim rather than relying on its label alone.
- Keep the extension fixture copied/separate from `consistent/`; preserve Mira's original two events and add the witness/registry perspective as new cited records. Use a new event ID, a nonnegative tick consistent with dependencies and entity/place occupancy, and ensure any dependency names one unique earlier event.
- Make the excerpt artifact explicitly marked as invented in-world source text, keyed by the exact source IDs referenced in JSON. Quote or describe the precise assertion supported by each relevant excerpt; source metadata and citations alone do not demonstrate correspondence.
- Avoid claiming the checker verifies textual support or canon truth. Treat any discrepancies between excerpt and structured claim as something for human review, not something this checker resolves.
