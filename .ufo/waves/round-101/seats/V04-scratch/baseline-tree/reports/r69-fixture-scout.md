# Round 69 fixture scout — controlled ledger-reference pairs

## Scope and evidence

This is a report-only fixture design; no fixture files were written or changed. The active checker is `.shokunin/lore/corpus/fixtures/check_bible.py`. Its per-side structural validation is at lines 111–126 (nonempty string `event_id`; `field` in `place_id`, `tick`, `depends_on`); its unconditional same-reference test is at lines 139–143 (two dicts whose `.get('event_id')` and `.get('field')` compare equal). Thus invalid sides may still reach the latter test. The proposed gate must require both sides to meet those two local structural conditions before comparing references; it must not require event existence/source resolution, which is a separate check.

Useful existing inputs: `.shokunin/lore/corpus/fixtures/r62-loaded/contradictions.json` contains one ledger record with two locally valid, different pointers (`tarin-envelope-observation/place_id` and `sella-bell7-presence/place_id`); its `timeline.json` includes both event IDs. `.shokunin/lore/corpus/fixtures/r62-malformed-side/contradictions.json` has two identical invalid `bogus` fields and the same event ID, while its `timeline.json` is malformed. Current replay of that fixture prints the timeline load error, two field errors, and `claim_a and claim_b references must differ` (four violations). It is a useful malformed-both pattern but not a controlled comparison because its timeline is also unavailable. `.shokunin/lore/corpus/fixtures/contradictions-ledger-malformed/contradictions.json` supplies two valid side shapes with different references; its loaded timeline has the `arrival` pointer and not `absent-event`, useful as a loaded-index warning control, not a clean matched base.

Keep a valid loaded timeline with exactly one row for each base event ID, so the ledger tests do not confound unavailable-table status. JSON `event_id` empty string is schema-valid JSON but structurally malformed per this checker's required-nonempty rule; `bogus` is an invalid assertion field. These are deliberately independent local defects in the malformed-both case. If the aim is to attribute the extra finding to one malformed dimension at a time, add matched malformed-both subcases with (a) identical empty IDs and allowed fields, and (b) identical nonempty IDs and invalid fields. In the malformed-one row, field validity is shared and the empty ID alone makes one side malformed. The expected exact local finding is `contradictions[0].claim_a.event_id: required nonempty string` (and, for malformed-both, additionally each `.field: expected one of [...]`). The current extraneous finding is `contradictions[0]: claim_a and claim_b references must differ`.

There is a logical constraint worth making explicit: under the proposed local predicate, a one-side-invalid pair cannot also have equal `(event_id, field)` values to a valid side. Equality on both raw values means both sides either pass or fail the same two structural tests. Consequently, malformed-one is a useful retention/control case but cannot itself demonstrate removal of the same-reference message; malformed-both with equal malformed values is the discriminating case. Do not manufacture a malformed-one/equal-reference example by using a non-dict value: the current same-reference branch already requires both sides to be dictionaries.

## Controls, limits, and falsifiers

The valid-same pair is essential to show that genuine duplicate references remain diagnosed; valid-different shows no spurious finding on ordinary distinct pointers. Prefer both sides to name existing unique events in those controls, so event/source diagnostics do not obscure the target line. If `r62-loaded`'s source table makes `missing-sella-note` unresolved, that is an unrelated source diagnostic; retain it byte-identically in all copies or select another known-good fixture, and compare only the target finding as well as the full output tuple. The fixture `r62-loaded` itself appears in the Round 62 executor/reviewer evidence as retaining the loaded event-source branch; it is not asserted here to be clean.

A useful additional non-target control is malformed-both with unequal malformed references (e.g. empty ID vs numeric ID) to show local validation survives with no same-reference finding. Do not let failures in timeline loading, whole-file schemas, or event existence substitute for the ledger-local structural test.

The proposed test can show only how checker input-ledger diagnostics behave. It cannot show story contradiction, event occurrence, source-text support, truth, canon, chronology, rights, or game mechanics. A calibration gain is not established by new output wording alone: it depends on demonstrating that suppressing the duplicate-reference conclusion for unusable pairs avoids an unsupported input-ledger claim while preserving local malformed-side errors and valid identical-reference detection. Falsifiers include loss of the valid-same finding, any lost per-side malformed finding, a same-reference finding retained for the identical malformed-both case under the proposed gate, or a change to unrelated diagnostics without an explained cause.
