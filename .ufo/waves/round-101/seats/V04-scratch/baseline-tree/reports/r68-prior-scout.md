## Novelty assessment and falsifiers

**Narrow rule novelty: supported, not falsified by the inspected prior rounds.** The active checker has a specific branch for non-string dependency members and a separate unknown-ID branch for strings, but no nonempty-string condition on a dependency member. R20 did not alter that resolution policy; R22 intentionally preserved existing lookup for every string; R63 and R64–67 did not add a dependency-member rule. Empty and whitespace-only IDs therefore appear to be an unaddressed input-validation case, distinct from both invalid member type and nonempty unknown ID.

**Material calibration gain: unresolved.** Existing `unknown event ''` (or whitespace) does signal that no indexed event has that exact ID; a reviewer could regard it as sufficient to repair the bad reference. A field-local “required nonempty dependency ID” diagnosis would more directly identify a malformed input field, but that improvement should not be assumed from naming alone. Matched empty, whitespace, and nonempty-unknown inputs should establish the exact baseline outputs and whether the proposed diagnosis changes the repair interpretation. Confirm self/repeated semantics if the new structural diagnostic is applied before or alongside lookup, and preserve valid-ID behavior. Falsify materiality if the existing unknown-ID message is already judged independently actionable with no meaningful ambiguity removed, or if the candidate adds misleading claims about event absence. Falsify narrow novelty only if a prior pinned checker/fixture or report demonstrates that blank dependency members already receive a distinct required-nonempty finding.
