# Round 19 schema scout — numeric tick and dependency behavior

## Raw observations

Inspected the declared baseline checker at `9ee1e6e:.shokunin/lore/corpus/fixtures/check_bible.py` (the Round 19 LOG baseline).

- The timeline required-field screen uses exact Python type identity: `type(row[field]) is expected`. For `tick: int`, JSON integer values pass; JSON booleans (`true`/`false`) do not pass despite Python's `bool` being an `int` subclass; JSON floats do not pass, including an integral-valued float such as `1.0`. A row failing any required-field test is not appended to `data['timeline']`; it therefore does not enter event indexing, event-ID counts, occupied-slot processing, or dependency processing. It receives the required-field diagnostic (`required nonempty int`).
- A negative JSON integer passes that schema screen. The row is retained and indexed; later the timeline loop emits `timeline[i].tick: must be nonnegative`. The checker does not use that finding to mark the row invalid or skip subsequent logic.
- Occupancy runs after entity/source checks and after `depends_on` is checked to be a list of strings. If dependency contents are not all strings, the loop `continue`s before occupancy and dependency checks. Otherwise, occupancy compares/stores `(entity_id, raw tick)` when the actor ID is unique and the place ID resolves uniquely to a place. There is no nonnegative-tick condition on this guard. Thus negative integers can participate in slot conflicts; malformed dependency contents can independently suppress that row's occupancy processing.
- Dependency validation is separate from occupancy and uses unique accepted timeline IDs. Unknown and duplicate event IDs are diagnosed. For a unique dependency, inversion is tested by the raw comparison `events[dep]['tick'] >= row['tick']`; no validity/nonnegative filter is applied to either event. Consequently an accepted negative tick can affect the inversion result. Boolean/float tick rows are absent from the timeline index, so a dependency to their ID is unknown (unless another accepted row with that ID supplies it).
- The required-field screen is not an overall “valid row” gate for timeline semantics: it admits negative integers, while the later negative-tick diagnostic is report-only. This differs from the provenance sub-record path, which explicitly checks `type(tick) is int or tick < 0`, marks the record invalid, and skips chain comparison for that record.

## Recommendations (not observations)

- For the declared Round 19 move, a narrowly scoped occupancy guard on the timeline row's negative integer tick is consistent with the current checker boundary: retain its diagnostic and raw row, but do not compare/store its occupied slot. Leave exact-type screening unchanged. This alone bounds the proposed finding to admitted nonnegative tick values without changing the global schema or dependency policy.
- Keep dependency inversion behavior unchanged in this round. The proposal concerns occupancy evidence; changing dependency participation or interpreting a dependency to/from an invalid-time event would be a second policy decision. In particular, do not claim this occupancy guard makes the negative event generally invalid or conflict-free.
- Paired evidence should isolate occupancy: same actor and distinct uniquely indexed place entities at a negative tick should no longer produce `double-booked`; the otherwise equivalent nonnegative pair should still do so. Include an accepted negative-tick event beside a valid dependency case if checking that dependency behavior remains unchanged, and keep malformed-type cases distinct because they are screened out before downstream logic.
- The scope analysis is static against the cited baseline. It does not establish paired CLI outputs, hidden-conflict coverage, or any canon/source conclusion.
