## Decision and calibration judgment

**Conditional GO to a small, source-table-only candidate; not a blanket NO-GO or current-rule admission.** Concrete novelty is not merely that a failed table cascades: r5 documented malformed-input cascades, r31/32 documented missing versus loaded-empty and admitted-row source-ID ambiguity, and r39 documented the distinct ledger zero-source rule. The new testable question is whether the checker distinguishes *unavailable source index* from a *successfully loaded empty index*, across direct and ledger consumers. Probe shows current checker does not: both yield identical “unknown” cascades, while the unavailable input separately gets its load error. This risks presenting absence as an index conclusion when there is no index to query. It is a calibration opportunity, not evidence that any cited record exists or that any claim is true.

**Falsifier:** hold all four other tables byte-identical and compare source input missing, malformed JSON, parsed non-array, loaded `[]`, loaded partial (`courier-log` only), and loaded duplicate IDs. A candidate must retain source-load/schema diagnostics; suppress only source-index-derived unknown/ambiguous results when unavailable; preserve loaded-empty unknowns, loaded partial membership results, and loaded duplicate ambiguity; retain independently testable entity, relation, timeline, provenance-shape/holder/tick, and ledger event-pointer/shape findings. Include an `allied_with` pair to prove unavailable status neither invents a reciprocal nor hides independent structural diagnostics. If no differentiated output is observed, if empty/partial loaded-array behavior changes, or if independent checks disappear, reject. A proper paired replay of all 103 fixture directories / 514 JSON paths and prior raw output tuples remains necessary before admission; this report did not run it.

Potential harms: withholding local unknown findings loses affected-reference triage; a single file error identifies the failed table but not its consumers. Suppressing ambiguity when the file is merely malformed would also lose evidence from any parseable subset—though JSON parse failure gives no trustworthy complete array. Keep the error explicit, retain independent structural checks, and do not call the bible clean. Most importantly, unavailable must not be conflated with loaded-empty. For alliance qualification the relation-level impact requires dedicated controls; do not assume the narrow direct-caller rule settles it.
