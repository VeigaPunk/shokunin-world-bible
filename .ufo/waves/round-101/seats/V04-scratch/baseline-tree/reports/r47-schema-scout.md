# Round 47 schema scout — item envelope representation

## Finding

**Schema feasibility: conditional GO for a narrowly attributed documentary report; NO-GO for treating it as evidence that Tarin and the slip refer to one envelope or occasion.** The JSON shape can encode a source-cited item claim and a reporter-attributed timeline observation, but it has no typed observation/provenance link or item subject on timeline events. Any use is editorial mapping, not machine-validated entailment. Thus feasibility alone does not establish the candidate's required distinct depth; likely depth is **unproven** until a reviewer finds a real object-specific comparison function beyond adding another report/source. Do not construct/claim a gain on schema feasibility alone.

## Path and limits

- Checker declares exactly four kinds (`character`, `place`, `faction`, `item`) and timeline fields `id,tick,entity_id,place_id,depends_on,description,source_id` (`corpus/fixtures/check_bible.py:7-14`). An `envelope` item is representable, but `entity_id` is still validated merely as an existing entity/actor ID, not as a reporter or event participant with a role (`check_bible.py:229-245`).
- Sources, entities, relations and timeline each cite one `source_id`; claim source references are also cited (`check_bible.py:54-90`, `101-117`; `entities.json` rows in fixture). There is no structured claim-to-excerpt/clause pointer, source independence/authentication field, reporter field, observation-target field, or provenance edge. A source citation says which fictional source supplied the row, not that it is true or independent.
- Relations have only `from,to,type,source_id` (`check_bible.py:11`); they cannot encode “slip reports envelope at desk” with observer, confidence, and occasion. Do not add a `deposited_by` or equivalent relation: the slip explicitly leaves depositor unrecorded.
- Existing timeline conventions put the reporting witness in `entity_id` and explain the reported observation in prose, e.g. Tarin in `r33-tarin-envelope/timeline.json` event `tarin-envelope-observation`; Jorin likewise reports Vela, not Vela as event actor, in `r43-jorin-vela-sighting/timeline.json` event `jorin-vela-sighting`. This is the least misleading shape for a first-person slip reporter. It remains a convention, not an enforced semantic rule.

## Fixture evidence / precedent

- R33 source excerpt says “I, Tarin, saw Sella place an unlabeled paper envelope…”; its map explicitly says the envelope is described only, not separately identified, and tick 3 is arbitrary (`fixtures/r33-tarin-envelope/tarin-note-excerpt.md:1`; `clause-map.md:3-11`). JSON has no envelope item: its `tarin`/`sella` claims and reporter event are cited to `tarin-note` (`entities.json` lines 45-66; `timeline.json` lines 24-33). This is prior art for an attributed report, not a separately individuated object.
- R35 adds shared Bell-7 wording to Tarin and Sella's opposing-location reports, but the clause map expressly says the label/date is a source claim, not authenticated chronology, and tick 3 does not encode Bell-7 (`fixtures/r35-bell7-conflict/clause-map.md:1-13`; `timeline.json` lines 24-40). Do not infer that a new slip's Bell-7 label establishes same occasion.
- R43 Jorin event uses `entity_id: jorin`, `place_id: harbor`, prose for the claimed Vela sighting and `source_id: jorin-note`; the Jorin clause map says same Bell-7 label does not establish shared occasion and broad harbor is editorial scene alignment (`fixtures/r43-jorin-vela-sighting/timeline.json:48-57`; `jorin-clause-map.md:4-10`). This supports reporter-as-actor only, not object identity.
- R10 uses a cited registrar-copy claim and a Sella-attributed timeline entry for Sella's recorded observation (`fixtures/r10-registry-witness/entities.json:45-56`; `timeline.json:24-33`). R23's absence-note claim/event carefully bounds “did not find” as a report and not proof of objective absence (`fixtures/r23-note-class/entities.json:45-55`; `timeline.json:24-33`; `witnessed-absence-clause-map.md`). A “depositor not recorded” clause must receive the same non-inference treatment.
- The r47 declaration itself requires separately sourced fictional slip, no depositor attribution, no envelope/occasion identity, and says a new source/row alone is not depth (`LOG.md:788-791`).

## Safe mapping if separately authorized

1. Add a new `item` entity `envelope` only as a **generic described class** (“unlabeled paper envelope”), not a unique physical object asserted to be Tarin's. Cite its attributed descriptive claim to the slip. `first_appearance` is a schema-required local source pointer, not proof it first existed then.
2. Add a source row identifying the slip as newly authored in-world fiction / unverified report, with explicit limits. Excerpt should state only that writer reports an unlabeled envelope lying on desk during what writer called Bell-7, and depositor was not recorded. Do not claim depositor absence, proof nobody deposited it, or identify author/reporter unless the excerpt actually supplies that first-person identity. The proposed Jorin-as-reporter is unsupported unless the authored excerpt names Jorin; an invented author attribution would be an extra premise.
3. A timeline event can set `entity_id` to the named reporter (only if stated), `place_id` to harbor, and description to “reports that an unlabeled envelope lay… during what [reporter] called Bell-7; slip says depositor not recorded.” Cite it to the slip; `tick` is only a local sequence value. Do not put the envelope in `entity_id` (it is not an actor) or assert Sella/depositor as actor. If no reporter is supplied, omit the event rather than invent an actor; an item claim alone may carry the report, but loses timeline semantics.
4. A side-by-side editorial comparison may say the two sources separately report envelope-like objects at the desk. It must explicitly withhold same object, same Bell-7 occasion, same writer/reporter/depositor, and any corroboration of Tarin's claim that Sella placed it. Matching generic wording/place/label is not an identity key. The schema cannot enforce these caveats.

## Risks and falsifiable gate

**Risks:** false identity bridge from generic noun and shared desk/Bell-7 label; event actor misread as depositor or envelope mover; fiction presented as recovered/authenticated record; “not recorded” inflated to objective absence; generic item row creating appearance of object identity; extra row/source counted as depth despite r10/r33 precedent; tick conflated with occasion. Checker CLEAN would establish structural/citation consistency only, not any of these semantics.

**Go only if** a non-author reviewer can state a concrete new question answered by juxtaposing the two independently attributed object-presence reports that is not merely “another witness/source says envelope,” and can identify what decision the item-level comparison enables without requiring same object/occasion. The map must show every assertion linked to literal slip language and preserve all identity/recording caveats. Otherwise **no-go** and omit the event/fixture. Falsifier: if changing the slip's generic object description or Bell-7 label leaves the supposed comparison unchanged, or if the asserted conclusion requires same object/occasion, it is not a grounded object-specific depth gain. Even on go, only narrow depth could improve; calibration/coverage unchanged, and no canon, source authentication, rights, or Sella/Tarin truth conclusion follows.
