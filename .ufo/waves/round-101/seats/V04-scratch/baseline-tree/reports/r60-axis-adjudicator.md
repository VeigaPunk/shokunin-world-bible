## Actual mechanism, tradeoff and axes

The diff introduces `entities_available`, set true only after `entities.json` decodes to a top-level list, **not** by index nonemptiness. Failed read, Unicode/JSON parse, duplicate-member rejection and nonarray leave it false; valid `[]` and arrays with valid or rejected rows leave it true. The candidate gates relation endpoint membership/ambiguity, allied-faction reciprocity eligibility, timeline actor/place membership/ambiguity/kind and derived occupancy on that status. Provenance iterates retained valid entity rows and naturally has none after a whole-file entity failure; it is not a global provenance early return. Relation and timeline source lookups, timeline tick/dependency checks, other loaded-table schema/index checks remain outside the gates. Thus the independent-fault fixture directly rebuts broad suppression, and the 99-case raw replay bounds measured collateral change. README's **parent-added clarification** correctly says that a parsed top-level array with malformed rejected rows is still available: references present only in rejected rows may be called dangling from the *retained valid input index*. It does not claim that loaded arrays are complete fictional-world registries.

**Calibration — materially improved, no material harm demonstrated.** The prior checker reports six definite *input-index* dangling conclusions when the required entity index cannot be loaded, exactly as for a valid empty index; r5 and r59 had already documented this misleading cascade, so discovery alone is not the gain. The gain is the now-verified distinction in actual output under byte-matched controls: unload retains its actionable primary failure but does not present inability to look up IDs as six established missing references, while legitimately loaded empty and partial arrays retain all their previous reference findings. Independent negative tick, source, and event dependency findings remain. This is a consequential change in what a validator tells a reader to repair, beyond a cosmetic reduction in count. The r59 nested case's six removed lines can be useful as a rough list of references affected by the unavailable table, so their loss is a real diagnostic visibility cost. But they were not reliable missing-reference findings, every current result still exits 1 with the direct load error, and loaded-table diagnostics and independent faults are retained. On the measured inputs that cost does **not** constitute a material calibration harm; output does not individually mark skipped checks unassessable, a remaining clarity limitation rather than CLEAN or claimed resolution.

The prior/regression/critic NO-GO broad warning remains right: analogous unavailable source/timeline indexes can still cascade, and this patch does not address them. More importantly, an array whose malformed rows were rejected is counted as loaded, so lookup into its surviving rows can still say dangling for an ID in a rejected row. The policy is specifically *whole-table parse/top-level availability*, not proof every row is usable. Existing duplicate entity IDs in a loaded table retain old ambiguous-reference logic; no new duplicate-ID fixture was added, so preservation rests on unchanged code paths and 99-case replay rather than a dedicated r60 pair. An authoritative contract that defines a failed entity table as deliberately empty, or evidence of independent findings masked under entity failure, would reverse admission; the examined README and probes do not show one.

**Depth — unchanged. Coverage — unchanged.** There is no new world fact, additional source-text inspection or source-authority test, or expanded table family; this is calibration of existing structural checker diagnostics. Neither a loaded-table missing ID nor an unavailable lookup establishes real or fictional-world absence. Local integer ticks, reference membership and source IDs do not establish chronology, source-text support, truth, canon, rights, licenses or permission.
