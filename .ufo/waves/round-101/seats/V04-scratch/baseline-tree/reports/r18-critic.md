# Round 18 critic — ambiguity certainty and fixture boundaries

## Raw observations (not recommendations)

- The current checker indexes every required-field-screened entity row by `id`; duplicate IDs overwrite the index value but increment `entity_id_counts`. For timeline `place_id`, count > 1 emits `ambiguous place entity`. The current occupancy predicate is `actor_id_count == 1 and place_id_count != 0 and comparable_place`; `comparable_place` is true for counts other than one. Thus an ambiguous nonzero place ID can still be stored/compared as a raw string and can yield `double-booked` against a different raw ID. This establishes an overconfident checker output for a non-unique identity, not that two real places or a real conflict exist.
- Round-17’s `r17-valid-places` / `r17-wrong-after` is a clean paired precedent for fixture discipline: only `timeline[1].place_id` changes (`tower` → `mira`), while descriptions explicitly say “Fixture input” and disclaim source-text location. Here no r18 fixture directories or r18 raw-run transcript were present when inspected, so I cannot confirm the declared paired inputs, row-order behavior, saved outputs, or output preservation for this round.
- The count-zero boundary is observable in `r16-missing-place`: a dangling `unlisted` place diagnostic, no double-booking; the known place control reports harbor/tower. The count-one wrong-kind boundary is observable in `r17-wrong-after`: `not a place 'mira'`, no double-booking, while `r17-valid-places` reports the known pair. These outputs are direct checker observations; no r18 regression replay has been performed here.
- Existing `r11-unique-nonplace` has `place_id: "mira"` (a character), but description “Mira departs the harbor.” Its source ID is `courier-log`; the file contains no source excerpt. The checker reports `not a place`, but neither citation ID nor description establishes that the cited text says “harbor.” `r11-place-character` likewise has duplicate `harbor` rows (place and character) and a source ID, not source-text evidence. These are not suitable evidence of real places or citations supporting a claim.
- The r18 declared question concerns duplicate/ambiguous place identity, while duplicate place rows can have different kinds, names, or claims. A raw place ID that is duplicated is not a unique place identity. Excluding it from definite occupancy comparison would be conservative, but does not establish there is no conflict; it leaves that possibility unassessed. Conversely a known-known comparison passing around an ambiguous middle row proves only the tested sequence and ID-level rule, not arbitrary pairwise behavior.

## Falsification / limits

The certainty claim would be falsified if an ambiguous place row still seeds or compares occupancy, in either ordering against a distinct uniquely resolved place; also check the ambiguous row itself is retained with its ambiguity diagnostic. A superficially paired fixture could mislead if it changes descriptions, source IDs, actor, tick, row order, or other data alongside the place ID. A fixture description phrased as a narrative assertion (“at Harbor”) or a `courier-log` citation with no excerpt would recreate the known prose/citation mismatch; input-only wording and explicit limits are needed. Check exact one-field diffs and inspect all JSON, not only CLI output.

Adjacent boundaries matter: count-zero missing IDs should retain dangling findings and remain out of occupancy; count-one wrong-kind IDs should retain `not a place` and remain out; count-one valid place IDs should preserve the known-place positive control. Neither the proposed ambiguity change nor these finite examples establish location, source-text support, canon, no hidden conflict, or broad soundness. Duplicate actor IDs are a different axis and must not be silently recast as this place-ID result.

## Recommendations (separate from observations)

- If a probe/fixture is authored, use an exact paired control differing only in one timeline `place_id`: unique valid place versus a duplicate ID. Exercise ambiguous-first and ambiguous-after order; add a known/ambiguous/known sequence only if its purpose is explicitly limited to preserving that tested known pair. Keep descriptions neutral (“Fixture input …”), and treat `source_id` as an identifier rather than an attestation absent excerpt evidence.
- Replay the existing 39 baseline fixtures and all new cases against saved raw output; explicitly compare count-zero, unique wrong-kind, valid known-place positive control, and ambiguity diagnostic/raw-row retention. Inspect exact JSON diffs and distinguish an unassessed possible conflict from a proven absence.
- Do not infer axis admission from this critique. On evidence currently available, the proposed calibration improvement is plausible but not yet demonstrated by r18 paired fixtures or a non-author replay.
