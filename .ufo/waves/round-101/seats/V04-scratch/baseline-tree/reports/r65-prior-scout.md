# Round 65 prior-scout — alliance source convention, novelty, qualification

## Verdict

**NO-GO for material calibration change.** The proposed forward-source gate is a plausible policy choice, but the prior alliance convention and current checker do not establish that a missing-reciprocal finding should be conditional on the *forward* row’s source resolution. More importantly, no concrete operator repair benefit is demonstrated; withholding the finding would remove a pointer to the missing reverse edge. This is not a source-prose, canon, or rights conclusion.

## Evidence and precedent

- **Round 2 (coverage rule, not source qualification):** `reports/r2-axis-adjudicator.md` says the new narrow convention requires a reversed `allied_with` row “with a source ID in the source index,” for distinct, unambiguous faction endpoints. The old checker lacked an alliance test; `ally-one-way` produced the new missing-reciprocal finding and `ally-reciprocal` was clean. This states membership-level qualification, not uniqueness and not a rule that the forward citation must resolve.
- **Round 7 (reverse-witness qualification):** `reports/r7-alliance-scout.md` records an actual temporary duplicate-source reverse-only probe: uniquely sourced forward edge, duplicate-ID reverse edge; output was only `sources[2].id: duplicate sources id 'harbor-compact'`, with no missing-reciprocal diagnostic. `reports/r7-axis-adjudicator.md` then admitted the narrow calibration move: only a *uniquely resolved reverse* is a sourced reciprocal witness. It explicitly says this is a source-ID qualification policy, not source-truth testing. The separate `r7-ally-reverse-ambiguous` case’s three findings are confirmed by `reports/r7-reviewer.md` and the verifier. This establishes the reverse witness convention; it does not settle forward eligibility.
- **Round 31 (generic relation citation):** `reports/r31-axis-adjudicator.md` and `reports/r31-source-scout.md` document a controlled `carries` relation pair. Actual ambiguous output includes `relations[0].source_id: ambiguous in-world source 'courier-log'` plus seven other findings (duplicate source and other affected references). R7 already covered an ambiguous alliance relation citation; r31 is novelty only for a controlled non-alliance relation class. It adds no forward-edge reciprocal policy.
- **Round 61 (table availability):** `reports/r61-prior-scout.md` characterizes source-table unavailability as a new testable status boundary, but explicitly distinguishes loaded empty/partial/ambiguous source indices, citing r31/r32/r39. `reports/r61-axis-adjudicator.md` reports the implemented source-only calibration gate and its matched controls: loaded source arrays preserve existing citation/reciprocal outcomes; unavailable sources withhold only source-index-dependent conclusions. That policy is about whether the index exists at all, not whether an available forward row has a unique ID.

## Current code and hypothesis gap

In `corpus/fixtures/check_bible.py`, every relation first receives ordinary source validation (`source(row['source_id'], location + '.source_id')`). The later alliance loop qualifies endpoints as unique faction entities, then searches for a reverse `allied_with` row whose source status is `unique` (the `any(... source_status(candidate['source_id']) == 'unique' ...)` predicate). If none exists, it emits `lacks a sourced reciprocal relation` when `sources_available`. It does **not** require the forward row’s own source status to be unique. Thus an ambiguous/unknown forward can currently yield both its direct citation diagnostic and the missing-reciprocal diagnostic; this is observable behavior, not evidence that the forward citation is valid.

The proposed gate would change only that derived finding for a forward row with unresolved source status. The competing interpretation is equally consistent with prior text: the relation row asserts an input edge, while only the sought reverse witness must be uniquely sourced. Removing the diagnostic may cost repair-pointer value (which direction/source edge must be supplied) without eliminating the direct source diagnostic. No matched operator task or probe output shows that this tradeoff materially improves decisions. Treat “forward citation must be unique before asking for reverse” as hypothetical policy, not settled convention.

## Materiality / falsifier

A material GO would require a matched probe showing that, for identical faction endpoints and reverse absence, changing only forward source status from unique to unknown/ambiguous makes the existing reciprocal finding misleading or harmful, and that withholding it improves the repair action while preserving direct citation and endpoint diagnostics. Conversely, if the missing-reverse pointer remains useful alongside the forward citation error—or operators need both source and relation repair cues—the gate is falsified. Also falsify any broad gate that suppresses the existing finding for unique-forward/reverse-absent, or suppresses the r7-established missing-qualified-reciprocal when forward is unique and reverse ambiguous. No such new probe output was supplied to this scout; do not assert either outcome experimentally.

## Recommendation

Keep current behavior for this round: **NO-GO before implementation** absent demonstrated repair benefit. Prior novelty is narrow and layered: r2 introduced reciprocal coverage; r7 uniquely qualified the reverse witness; r31 exercised a controlled non-alliance ambiguous citation; r61 gated conclusions on whole-table availability. None proves forward-source qualification should be gated. No source prose, fictional alliance validity/canon, real-world rights, or permission is inferred.
