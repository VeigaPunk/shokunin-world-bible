# shokunin-world-bible

Fictional-world records. Entities, relations, and timeline events, with a
mechanical consistency check and a separate ledger for real-world
inspiration.

Lane id: **lore-shokunin**. Rank: **shonen**. [`SHONEN.md`](SHONEN.md)
has two `[~]` author assertions and two open boxes. There is no root
`SKILL.md`. The executable surface is the checker and the decision notes
in `corpus/knowledge/`.

Fleet: [shokunin](https://github.com/VeigaPunk/shokunin). Languages,
myths, and costume systems are generated by
[kotodama-shokunin](https://github.com/VeigaPunk/kotodama-shokunin) and
handed off. This lane records them and checks consistency. It does not
silently pick a winner when two records disagree.

## The question

> Does every entity, relation, and event cite an in-world source, and do
> the declared constraints (place, alliance, tick order) hold — without
> the checker inventing a canon answer?

A contradiction is evidence for editorial review. The checker reports it.
Omit an uncertain assertion rather than file it as uncited canon.

## Boundary

**Owns:** fictional-world records and the consistency verification in this
repository. Real-world reference works are cited with attribution, rights,
and AI-training permission kept as distinct questions
(`corpus/knowledge/reference-ledger.md`).

**Hands off:** claiming canon without an in-world citation, resolving
contradictions by rewriting them, real-world rights rulings, and game
mechanics
([shokunin-godot-2d](https://github.com/VeigaPunk/shokunin-godot-2d)).
Sibling repositories and domain source trees are read-only.

## Run

The checker in this checkout is `corpus/fixtures/check_bible.py`. It
takes one directory argument: JSON arrays for sources, entities,
relations, and timeline. `corpus/fixtures/README.md` is the long-form
contract (what exits 0, what exits 1, and which rules are local
conventions). Its command examples use the historical
`.shokunin/lore/corpus/fixtures/` prefix. From this repository root the
same two fixtures are:

```sh
python3 corpus/fixtures/check_bible.py corpus/fixtures/consistent
python3 corpus/fixtures/check_bible.py corpus/fixtures/contradictions
```

The fixtures README states that the first exits 0 and the second exits 1,
printing every seeded violation. Further fixture families (alliance
reciprocity, item chains, tick order, duplicate members, and the rest)
are listed in `corpus/README.md` and spelled out in
`corpus/fixtures/README.md`. The checker does not modify the bible.
Rejected round-4 name inputs live only under `corpus/live/rejected-r4/`.

In-world `source_id` values point at fictional records inside the bible.
They are not the real-world reference ledger.
