# Round 60 critic — falsification of unavailable-table suppression

## Independent calibration verdict

**NO-GO for a broad or implicit suppression change on the evidence currently in scope.** A narrow status distinction could improve calibration, but the proposed move is not safe if it suppresses all diagnostics downstream of an unavailable table, or if it treats unavailable as empty. The current observable cascade is misleadingly phrased as definite dangling, yet suppression can hide independently actionable findings and cannot be limited by dependency from the current `[]` representation alone. The correct claim is only about checker input referential checks, not world existence.

All cases become indistinguishable from a successfully parsed empty table in `data[section]` at lines 32-43.

It means a failed entities load causes false-certainty *relative to unavailable input*, while row-local tick/dependency checks do not need the entities table and must not be suppressed wholesale.
- Replayed r59 evidence is recorded in `.shokunin/lore/reports/r59-axis-adjudicator.md`: current `r59-nested-duplicate` emits the `entities.json` duplicate `source_id` load error plus six dangling findings; pinned prior checker on those same bytes was CLEAN. A successfully loaded partial table can be intentional; the checker cannot infer that it is incomplete. Missing ID in a loaded table is a checker-input referential finding, not proof the entity does not exist in a wider world.

## Proposed policy and falsifiers

If suppression is pursued, it must be explicit tri-state/status handling (loaded, unavailable; and malformed-but-readable should remain unavailable, not empty), preserving the original load diagnostic. It may withhold only lookups whose target table is unavailable: entity presence/uniqueness/kind checks in relations/timeline/provenance, and source presence/uniqueness checks wherever `sources.json` is unavailable. It must retain local schema/type errors, nondependent tick/dependency validation, relation/timeline source-independent structure, and every check whose reference table loaded. No status may silently be described as absent or clean. Existing fields currently use list/index defaults, so simply `continue`-ing whole relation/timeline loops would hide independent findings (e.g. negative ticks, self/repeated/unknown dependencies, wrong field types); this is a concrete regression/cascade risk.

A decisive paired probe should hold all other bytes fixed and compare (A) duplicate/missing/invalid `entities.json` with references to `mira`, and (B) successfully loaded `entities.json` with `mira` deliberately omitted. A must retain the loader diagnostic and mark dependent entity resolution unassessable without dangling/ambiguous/not-a-place claims; B must retain dangling findings. Add a third A control containing negative tick and malformed/self/unknown dependencies to prove independent timeline diagnostics survive. Repeat analogously for unavailable `sources.json` versus loaded empty sources if source-reference suppression is included; otherwise explicitly defer it. Test a relations/timeline table load failure separately: do not infer that missing/unreadable rows mean the world has no relations/events, and preserve diagnostics from other loaded tables. Old fixture output changes and counts must be replayed and enumerated; r5/r59 evidence already predicts affected outputs.

**Falsifier of this NO-GO:** an implemented, independently replayed status-aware candidate demonstrates the paired distinction, preserves independent checks in the third control, scopes each unavailable target table correctly, and its cascade/old-output deltas are materially clearer without masking diagnostics. Conversely, one hidden negative-tick/dependency or kind/type error, or an unavailable case still labeled dangling/absent, falsifies safety. Until those observations exist, the present report cannot endorse execution or admission.

## Source/timeline and epistemic boundary

`entities.json` and `sources.json` are input tables. An absent referent in a successfully loaded table proves only non-membership in that supplied table; an unavailable table supports no such non-membership conclusion. The checker validates IDs and fields, not whether cited source text supports a claim (`README.md:36-54`), and local integer ticks are not absolute chronology (`README.md:29-34`). Neither suppression nor a dangling-input diagnostic settles source-text truth, actual world absence, canon, rights, license, or permission. A suppressed result should say “not assessable because table unavailable,” never “no entity/source” or “valid.”
