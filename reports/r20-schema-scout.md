# Round 20 schema scout — event IDs, tick screening, and dependency resolution

Baseline inspected: `47733bf:.shokunin/lore/corpus/fixtures/check_bible.py`, the Round 20 LOG declaration. This is static source-flow analysis; no paired CLI probe is claimed.

## Raw observations

- Each section is screened row-by-row against its required fields before it is admitted to `data[section]`. Required values must have exact Python type (`type(value) is expected`); strings must also be nonblank. A timeline row with a missing/blank/wrong-type required field gets a field diagnostic and is omitted as a whole. For `tick: int`, JSON booleans and floats (including `1.0`) fail; a negative JSON integer passes this structural screen.
- `index('timeline')` indexes only admitted timeline rows. A repeated admitted ID emits `timeline[n].id: duplicate timeline id ...`; the dictionary assignment replaces the prior mapped row with the later row. Separately, `event_id_counts` counts every admitted row, including duplicates. The `events` map and the count therefore have distinct roles. Event-ID uniqueness is local to the timeline table, not a global namespace check across all sections.
- `event_id_counts` is also used for contradiction claim references: exactly one admitted event row is required. A missing or malformed-tick event that was excluded does not count as a resolved event for these checks.
- In timeline dependency processing, `depends_on` must first contain only strings. A non-string member causes a row-level diagnostic and `continue`, skipping occupancy and all dependency checks for that row. For a string member, self-dependency is diagnosed independently. The first occurrence is resolved by count: zero gives `unknown event`; more than one gives `ambiguous dependency event`; exactly one resolves through `events[dep]`. Only the unique case can reach inversion comparison. Repeated references get a repeated-dependency diagnostic and are not resolved/compared again after their first occurrence.
- The inversion predicate is the raw integer comparison `events[dep]['tick'] >= row['tick']`. The source does not check either endpoint's tick validity first. Thus a retained negative integer endpoint still participates after the separate `must be nonnegative` diagnostic. A self-reference to a unique ID can also reach inversion (same tick compares `>=`), in addition to its self-dependency finding.
- Since malformed-tick rows never enter the timeline index or event counts, a dependency to an ID represented only by such a row resolves as unknown. If a separate admitted row has that same ID, only admitted rows determine the count; a unique admitted duplicate-name survivor can resolve, while two admitted rows remain ambiguous.

## Recommendations (not observations)

- To withhold only definite inversion when either endpoint has a negative tick, retain current ID counts, unknown/ambiguous/self/repeated findings and raw rows, but gate the `>=` comparison on both uniquely resolved endpoint ticks being nonnegative. Do not gate away dependency resolution or call the dependency satisfied when comparison is withheld.
- Keep required-field type screening separate: malformed `bool`/float/missing ticks are excluded upstream and yield existing schema/index consequences; they should not be conflated with admitted negative integer ticks. Keep duplicate-ID ambiguity independent of tick validity.
- A useful paired probe set would cover dependent-negative/prerequisite-valid and dependent-valid/prerequisite-negative; valid-to-valid inversion and valid chronological control; and duplicate/malformed-ID boundaries if the implementation touches resolution. Preserve self/repeated/unknown/ambiguous diagnostics. These recommendations do not establish event chronology, occurrence, source support, or canon.
