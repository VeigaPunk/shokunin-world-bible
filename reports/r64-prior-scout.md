# Round 64 prior-scout — malformed-row identity boundary

## Independent decision: NO-GO on prior art alone

I do **not** recommend advancing the proposed calibration change to implementation on the currently available prior-art evidence. A rejected entity row with a usable raw `id` is certainly evidence that the input contains that token, but current checker semantics intentionally index only schema-admitted rows. Treating such a row as making reference membership indeterminate is a new rule, not an automatic consequence of r60. The idea is plausible; material operator benefit over the existing row-local schema error plus dangling repair pointer is not established. No checker/fixture/README/LOG change is authorized or made here.

## Prior art and observed behavior

- **R26 is direct malformed-field/identity precedent.** `reports/r26-axis-adjudicator-retry.md` describes paired `r26-to-malformed` / `r25-to-ambiguous`: the sole entity change is `entities[4].name` from a nonempty string to `""`; the raw row retains `id: "seal"`. Current output for `r26-to-malformed` is only `VIOLATION: entities[4].name: required nonempty str` and summary 1. The valid duplicate in r25 instead produces `duplicate entities id 'seal'` and `relations[0].to: ambiguous entity 'seal'`. R26 admitted this narrow *existing checker* calibration: raw malformed duplicate is not a second indexed/admitted entity. It does not prove dangling is always the ideal diagnostic for references matching malformed rows, but it rules out counting raw IDs as valid identity/uniqueness evidence.
- I independently ran current `check_bible.py` on a temporary copy of `r26-to-malformed`; exit 1, exactly the schema error above, empty stderr. No repository files changed. This confirms observed current behavior, not a candidate output.
- **R60 is adjacent but explicitly bounded.** `check_bible.py:38-60` tracks whole-table load/top-level-array availability; row validation at `:65-80` appends only fully valid rows to `data[section]`. `reports/r60-loader-scout.md` says a loaded partial table retains findings against absent IDs in the successfully loaded valid-row index, while whole-table unavailability is distinct. `reports/r60-axis-adjudicator.md` admitted only unavailable-vs-loaded entity table handling and expressly says an array with rejected rows remains available, so references found only in rejected rows may still be called dangling from the retained valid input index. This r64 proposal would deliberately reopen that boundary.
- **R16–18 do not resolve malformed-row membership.** R16–17 narrowly withhold occupancy comparisons for unresolved/wrong-kind places while retaining their local dangling/kind diagnostic and valid known comparisons (`reports/r16-axis-adjudicator.md`, `reports/r17-axis-adjudicator-retry.md`). R18 counts required-field-screened rows; a duplicate *admitted* place ID makes identity ambiguous and gates the occupancy inference (`reports/r18-axis-adjudicator.md`). These are precedents for suppressing a dependent conclusion when the indexed identity is ambiguous, not evidence a rejected row should count as a matching entity. R26 clarifies that boundary.
- **R56 warns that local diagnostics need materiality evidence.** `reports/r56-precedent-scout.md` and `reports/r56-axis-adjudicator.md` found a local holder ambiguity message technically accurate but not materially better where the global duplicate-ID diagnostic and withheld chain comparison already exposed the issue. Not the same output proposal, but relevant: a more cautious/local message alone is not an axis gain; show it changes a concrete repair decision without masking useful findings.

## Observed behavior versus proposed rule

Observed: a successfully parsed entities array sets `entities_available` even when rows fail schema; invalid rows receive row-local errors and are excluded from `data['entities']` and its indexes. For a relation pointing to the ID of such a rejected row, the current checker can additionally say `dangling entity`; for timeline, holder, or alliance checks analogous consequences may arise where those checks consult the screened index. R60's whole-table gate does not suppress these because the table parsed as an array. The r26 temp probe confirms the rejected duplicate does not produce duplicate/ambiguous-ID findings.

Proposed: retain schema error but turn a reference to an ID occurring in any rejected row into `cannot assess ... matching entity row invalid` (or equivalent), while still excluding that row from all valid identity/kind/holder/place/faction/occupancy witnesses. This is a new raw-row side index/status. It could avoid wording a raw-present ID as absent from the retained index, but also risks masking a genuinely dangling reference merely because an unrelated malformed row reused that token. It could add state and field-specific messaging across several consumers; r60's availability boolean alone cannot implement it.

## Materiality test and falsifier

A future GO requires byte-matched temp pairs, including: valid matching row; loaded empty array; malformed row with referenced nonempty string ID; malformed row with no usable ID; valid duplicate ID; unavailable file. At minimum compare relation endpoint, actor/place timeline, holder and faction/alliance consumers; retain independent source, tick, and dependency checks. The crucial contrast is not just output wording: demonstrate a repair task where current `dangling entity` materially misdirects an operator despite the matching schema error, while the proposed invalid-row status points to the relevant malformed row without hiding an actual missing reference. Check malformed row with same ID but bad unrelated name separately from malformed kind/identity-critical fields; no malformed row may certify existence, uniqueness, kind, or occupancy.

Falsifier for the proposed GO: operator/reviewer evidence shows current schema-plus-dangling is an adequate actionable repair pointer, or the proposed raw-ID uncertainty would conceal a real absent reference / amplify noise without changing repair action. Conversely, a collateral-free paired task where current wording causes a materially wrong repair and the narrow status corrects it, preserving absent-ID dangling and all independent diagnostics, would overturn this NO-GO. No observed candidate outputs or cascade measurements exist yet.
