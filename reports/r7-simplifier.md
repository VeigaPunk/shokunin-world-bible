## Proposal (not implemented or measured)

Use one source-ID counting/indexing pass and one qualification predicate for every citation decision. Keep `index('sources')` (or its equivalent) responsible for the existing duplicate-ID finding, but do not treat its last-wins row map as proof of uniqueness. A compact representation is `source_id_counts` plus the existing rows/map; define one helper that classifies a reference as unknown, unique, or ambiguous (`count == 0`, `== 1`, `> 1`). At each reference location, unknown keeps the existing unknown-source diagnostic; ambiguous gets a local “ambiguous source ID” diagnostic and is non-qualifying; unique qualifies.

Route entity first-appearance/claims, relation citations, timeline citations, provenance source IDs, contradiction-linked event sources, and the alliance reciprocal witness through that shared predicate. In particular, alliance reciprocity should require the candidate edge’s source to be unique, not merely present. Avoid separate source-count dictionaries, special per-feature validators, or changing source records: those would recreate inconsistent qualification rules. Retain both duplicate records and the original duplicate-ID violation.

Minimality boundary: this only answers whether an ID identifies exactly one listed source record. It does not attest that the record supports the claim, prove canon truth, choose between documents, or revise alliance/provenance semantics. Before accepting the change, add paired unique/duplicate source fixtures that exercise at least ordinary citation and qualified witness behavior, then replay all existing fixtures. Those are recommendations, not observed tests.
