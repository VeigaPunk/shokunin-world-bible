# Round 16 citation/identity scout — IDs, names, and truth

## Observations (raw evidence)

- In `.shokunin/lore/corpus/fixtures/check_bible.py`, the input screen first retains rows that have required fields of the right Python types (`check`, `FIELDS`, and `data`). `index('entities')` builds the entity-ID lookup from those screened rows and separately emits duplicate IDs. For each timeline event, `place_id` is tested against this entity index: absent ID → `dangling entity`; count above one → `ambiguous place entity`; count exactly one → inspect that target's `kind` and report `not a place` unless it is `place` (the `occupied` loop). It does not use the entity `name` for this resolution.
- Raw CLI from repo root, `python3 .shokunin/lore/corpus/fixtures/check_bible.py .shokunin/lore/corpus/fixtures/r11-dangling-place`, emitted `VIOLATION: timeline[0].place_id: dangling entity 'unlisted'` and `1 violation(s); no canon changed`. The fixture's `entities.json` has `harbor`/`Lantern Harbor` and `tower`/`North Tower`; there is no entity with ID `unlisted`. This is a missing key, not a missing display name or a claim that the harbor is fictional/nonexistent in canon.
- Place ambiguity and wrong-kind are distinct observed cases: CLI on `r11-place-character` and `r11-character-place` reports duplicate entity ID `harbor` plus `ambiguous place entity 'harbor'` in both row orders; `r11-unique-nonplace` reports `not a place 'mira'`. The fixture JSONs show `harbor` reused by place and character rows, while `mira` uniquely resolves to a character. The checker never selects one duplicate based on order.
- Source IDs are a separate namespace/lookup. In `check_bible.py`, `sources = index('sources')`, `source_id_counts` and `source_status` classify source IDs as unknown (0), unique (1), or ambiguous (>1); `source(...)` reports unknown/ambiguous citation IDs. The checker validates the source-row shape and ID reference, but does not read cited source text to verify support. For example CLI on `r7-item-ambiguous` reports duplicate source ID `archive-ledger` and affected references as `ambiguous in-world source 'archive-ledger'`; this concerns the source table, not an entity/place ID.
- Names are display fields in entity rows (`name: str` required). The active checker has no name index or uniqueness check; `r4` documentation in `fixtures/README.md` says the exact-name detector experiment wrongly flagged legitimate homonyms and was rejected, with only archived evidence. Thus equal names do not make IDs ambiguous, and different names do not repair an absent or duplicate ID.
- The CLI's final `no canon changed` / `CLEAN` language is borne out by `check()` returning diagnostics and the CLI printing them; it does not write data. `fixtures/README.md` explicitly says a clean result validates structure and citation-ID resolution, not truth of citations; manual wording correspondence does not establish independent corroboration or canon truth. Round 15 gives a concrete example: `r15-carbon-followup/timeline.json` cites `sella-carbon-followup`, and the source row's reliability note labels it newly authored, not recovered. ID resolution cannot upgrade that one authored account into verified canon.

## Recommendation (not observed behavior)

Keep these claims separate in any Round 16 rule or documentation: (1) a place reference is an entity-ID lookup; zero screened matches is dangling, multiple matches ambiguous, exactly one match permits a kind check; (2) a citation is a source-ID lookup with unknown/unique/ambiguous status; (3) `name` is not an identity key; and (4) none of these structural outcomes decides whether an in-world assertion is true. In the proposed occupancy calibration move, only a uniquely resolved place entity of kind `place` should qualify as a *known place* for a definite different-place comparison. A dangling, ambiguous, or uniquely resolved non-place key should not be described as a known place. Preserve the raw event and its local diagnostic; withholding a definite conflict is not evidence of no conflict, same place, or canon location. This is a scoped recommendation, not a report that the current checker implements it.
