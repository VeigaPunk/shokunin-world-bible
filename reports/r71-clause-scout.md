## Method from r43

Use the r43 pattern: quote each *exact* source span in a manual clause map, then point to the precise new JSON row/field(s); state what the span licenses and what it does not. Keep source attribution explicit in the entity claim and timeline description. The source row identifies the newly authored fictional report; every new claim/event should cite that source ID. Entity/event IDs, broad place alignment, and tick are editorial pointers—not independent evidence. See `.shokunin/lore/corpus/fixtures/r43-jorin-vela-sighting/jorin-clause-map.md`, `.shokunin/lore/reports/r43-scribe.md` (“Clause/source/JSON table”), and `.shokunin/lore/reports/r43-reviewer.md` (“Clause-to-record trace”). For r71, apply that method only to the new Vela report and its single new cited entity claim plus single new timeline event. Keep a map row per semantically distinct clause, with literal span and JSON pointer, not a paraphrase treated as a quotation. Do not use an existing Vela row as if it were evidence about the slate or its maker. Keep the five inherited tables/rows otherwise unchanged as the declaration requires.

For both rows, the evidence path should be: exact excerpt span → map row → exact JSON pointer → same new `source_id`. ## Falsifiers / exclusions

A non-author should reject or narrow the map if any new claim/event presents inferred maker as observed or settled; if quoted wording exceeds the literal source; if “readable” is converted into authorship/provenance/authorization; if a source pointer is missing/incorrect; or if an inherited row is used to imply the absent Vela response exists. Avoid factual canon, rights, and mechanics conclusions. The requested depth test is whether the attributed distinction between reported legible wording and Vela’s separately marked inference adds meaningful perspective—not whether the fixture has more rows or passes the checker. No conclusion on that test is possible from this scout alone.
