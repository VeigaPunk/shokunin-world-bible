# Round 16 simplifier report — occupancy guard

## Observed baseline

Raw checker: `.shokunin/lore/corpus/fixtures/check_bible.py`. In `check()`, the timeline loop already computes `place_id_count` from `entity_id_counts`, emits a dangling finding for absent IDs, emits ambiguity for counts >1, and emits `not a place` for a unique non-place. However, occupancy currently runs under only `if actor_id_count == 1`; it compares raw `row['place_id']` strings and stores the first `(location, place_id)` in `occupied`.

Observed CLI (the command is `python3 .shokunin/lore/corpus/fixtures/check_bible.py .shokunin/lore/corpus/fixtures/<case>`): `r12-unique-actor` exits 1 with `VIOLATION: timeline[1]: double-booked 'mira' at tick 7 in timeline[0] ('harbor') and 'tower'`; `r12-ambiguous-actor` reports duplicate/ambiguous actor and does **not** report double-booked; `r13-missing-actor` reports dangling actor rows and does **not** report double-booked; `r13-unique-actor` retains the definite double-booked finding. Thus the existing unique-actor eligibility rule should remain untouched.

Place-rule controls observed through the same CLI: `r11-dangling-place` reports `timeline[0].place_id: dangling entity 'unlisted'`; `r11-unique-nonplace` reports `timeline[0].place_id: not a place 'mira'`; both report no occupancy finding. `r11-place-character` and `r11-character-place` report duplicate entity ID and ambiguous place, with no occupancy finding. These controls constrain the patch: only a uniquely identified entity of kind `place` is a resolved place. Do not change their current findings or attempt to choose among ambiguous rows.

## Smallest guard recommendation

Keep `if actor_id_count == 1`, but make occupancy comparison/storage conditional on the current place being uniquely resolved **and** of kind `place` (`place_id_count == 1 and entities[row['place_id']]['kind'] == 'place'`). Compare with a prior occupied slot only when that prior slot was stored under this same guard. In compact form, gate the existing occupancy block with the current uniquely-resolved-place predicate; retain the existing raw ID inequality comparison inside it. This withholds a definite different-place assertion whenever either event has a dangling, ambiguous, or uniquely non-place location, while preserving double-booking for two distinct resolved place IDs and preserving the unique actor rule. The existing dangling/ambiguous/not-place checks stay outside the gate and therefore still report as before. Do not infer that the unresolved row is at the other place, at the same place, or conflict-free.

This is a recommendation, not a checker edit. I did not modify checker code, fixtures, shared documentation, or commit anything. Fixture CLI probes above were run against the working-tree checker; they do not establish the proposed guard's output or baseline-wide byte identity. A verifier should replay all 29 prior fixture outputs after implementation and explicitly probe a paired unique-actor/same-tick case with one missing place plus the two-uniquely-resolved-different-place control.
