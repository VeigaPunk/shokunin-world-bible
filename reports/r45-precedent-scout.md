# Round 45 precedent scout — faction occupancy novelty

## Scope and finding

Read-only comparison of the requested rounds. The proposed case is **not settled by these precedents**, but neither do they establish that every faction is distributed or that a faction timeline row means simultaneous membership/presence at several places. A guarded faction exception is a testable calibration hypothesis, not an established semantic rule. Require a narrowly explicit input convention (and preserve the character case); do not infer truth from source IDs or checker acceptance.

## Grounded boundaries and risks

The schema admits `faction` as an entity kind and timeline `entity_id` is a string (`corpus/fixtures/check_bible.py:7-13`). The active occupancy map applies to every uniquely resolved actor ID/tick and reports a different place (`check_bible.py:228-252`); it does not branch on actor kind. README says “A character cannot occupy different places at the same tick” and allows simultaneous records at the same place (`corpus/fixtures/README.md:29-34`). Read narrowly, this establishes a character rule; it does not state factions are singular, or that faction actors are exempt. The README separately states the examples are invented and citations resolve to in-world records, not proof of claims (`README.md:36-41`).

Thus a source passage explicitly describing separated faction outposts during one local watch would make a useful *fictional test input* for a proposed convention, but it would not authenticate itself or prove canonical truth. A checker exception based solely on `kind == faction` risks suppressing a genuine input inconsistency if faction events are intended to encode one singular location. Conversely, universal occupancy risks treating a collective as a single character. Keep the rule narrow and explicitly input-scoped; retain the existing character double-booking diagnostic exactly. Do not generalize to place/item/other actors, and do not label all factions distributed.

## Falsifiable recommendation

**Conditional go to controlled probing, not implementation yet.** First confirm baseline actually emits `double-booked` for two uniquely resolved faction rows at the same nonnegative tick and distinct uniquely resolved places, while a character twin does too. Then test the smallest defensible proposed exception only on faction actors: it must suppress that occupancy diagnostic for the candidate faction pair while leaving the character twin's exact diagnostic intact; duplicate actor IDs, invalid places, negative ticks and non-faction actors must retain their existing behavior. The fixture must state its own fictional convention explicitly and make no claim that the invented report is authenticated canon. If no source text/convention can distinguish distributed-presence events from a singular-position faction event, if the baseline does not produce the expected finding, if the character control changes, or if r21/r22/r24 existing outputs regress beyond declared scope, **no-go**. The checked-in precedents alone do not warrant a broad faction exemption.
