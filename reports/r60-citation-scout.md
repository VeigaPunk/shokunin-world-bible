# Round 60 — citation scout: input availability is not world absence

## Independent calibration judgment: GO, narrowly

**Observed evidence.** The checker requires five tables (`FIELDS`, `check_bible.py:20-24`); it loads each file in a loop (`:32-56`). On duplicate-member, read/Unicode, or JSON syntax errors it reports a table-local load error and assigns `rows = []` (`:36-43`). It likewise assigns `[]` after a non-array top level (`:44-46`). Downstream indexes are then built from successfully accepted rows (`:58-74`); `source_status()` maps zero indexed source IDs to `unknown` (`:76-84`), and entity endpoint checks map absent IDs to `dangling` (`:146-154`). Timeline entity/place checks similarly test membership (`:206-213`). Thus an unavailable `entities.json` is mechanically indistinguishable from a successfully loaded empty entity list for endpoint lookup: a parser/file error is followed by dangling-entity findings. That is a checker representation fact, not evidence that any entity is absent in the fictional world.

The r59 nested fixture repeats `source_id` within `entities.json` (`.shokunin/lore/corpus/fixtures/r59-nested-duplicate/entities.json:7-10`). The r59 LOG records that the parser rejects the entire table, substitutes `[]`, then emits six dependent dangling entity findings; it explicitly calls these downstream loaded-row effects, not six source mistakes or proof entities are absent (`.shokunin/lore/LOG.md`, Round 60 declaration and Round 59 closure). This is a concrete, already documented cascade. By contrast, the r5 citation scout tested an unresolved identifier in a successfully loaded entities table and explicitly limits the result to a reference-membership check, not source support (`reports/r5-citation-scout.md`, Observed/Limits). R5’s missing contradictions file is another table-unavailable case but does not establish a high-fanout entity cascade (`LOG.md`, Round 60 declaration).

**Proposed interpretation (not observed checker behavior):** represent table availability separately from row contents. For a table that did not load, suppress only conclusions that require lookup in that unavailable table (e.g. endpoint unknown/dangling, source unknown/ambiguous, or entity kind/identity determined from `entities`). Preserve the table-load error and checks grounded in other valid inputs. A loaded empty/partial table remains meaningful input and should still produce ordinary dangling/unknown findings for referenced IDs absent from it. This is a calibration improvement, not a claim that the data becomes valid or that a reference exists in canon.

The checker’s source IDs designate in-world fictional records (`fixtures/README.md`, “source_id and first_appearance” paragraph); membership is not textual evidence. Even a resolvable ID does not establish that the cited text supports a statement, nor source reliability, truth, historical reality, canon, copyright/license status, or AI-training/use permission. The separate reference ledger explicitly disclaims rights grants and permission inference (`corpus/knowledge/reference-ledger.md:3-8`). Neither unavailable input nor an unknown ID licenses a world-absence conclusion.

## Falsifier and boundary

A paired probe should demonstrate: (1) missing/invalid/unloadable `entities.json` yields its load diagnostic without labeling every dependent ID definitely absent; (2) loaded empty/partial entities still reports the same genuine missing-reference findings; and (3) independent schema, citation checks over loaded tables, event dependency checks, and parser diagnostics remain. If safe suppression cannot be scoped to the unavailable table, or suppresses checks supported by loaded data, this GO is falsified. A checker design that already carries explicit table-load status through lookups (contrary to the inspected `rows=[]` path) would also falsify the proposed diagnosis. Equivalent unloaded `sources.json` cases need a paired probe or an explicit deferral; do not generalize this evidence to every table.

## Regression / cascade risk

This is a recommendation, not an edit or test execution. Suppression may remove useful cascades that help locate defects; the output should make the unavailable lookup explicit rather than silently omit all errors. It must not turn invalid/missing input into CLEAN, choose among duplicate JSON values, or change loaded-empty semantics. Check all existing fixture stdout/stderr/exit tuples and raw fixture bytes; the intended r59 nested-duplicate change is bounded to dependent lookup findings, with the duplicate-member parser error retained. Risk includes masking independently meaningful checks (e.g. timeline-local malformed values) if suppression is implemented as broad early return, and leaking stale indexes if one table load fails. No fixture, checker, README, or LOG was changed by this scout.

**Recommendation:** GO to a narrow paired calibration probe only; do not treat it as permission to implement globally until the affected lookup families and cascade tradeoff are verified. No source-text support, fictional-world absence, canon, rights, or permission conclusion follows.
