## Independent material calibration verdict

**GO, narrowly, for a paired diagnostic probe—not yet a claim that the checker should ship.** A global duplicate-ID message identifies the duplicated entity declaration, but not which provenance record’s `to_holder` or `from_holder` is blocked. Since the chain check is deliberately withheld, a precise local ambiguity at the affected reference improves operator calibration by distinguishing unresolved multiplicity at that field from dangling (zero matches) and resolved (one match), while retaining all raw provenance and global diagnostics. It should emit at each affected non-null holder reference, not null `from_holder`; preserve the existing chain suppression. Do not count this as new coverage or depth. If the probe produces noisy duplicates without clearer location/value to an operator, or changes chain findings, withdraw the GO.

Minimum falsifier: starting from `item-chain-valid`, append one complete, schema-valid entity row whose ID equals a referenced holder; compare unique control, duplicate only at `to_holder`, duplicate only at `from_holder`, and (only if needed) both references duplicated. Expect local ambiguity only at duplicate referenced fields, global duplicate retained, no chain comparison through an ambiguous record, and identical outcomes for unaffected unique/unknown references. A malformed same-ID row is a negative control and must not trigger holder ambiguity. The claim fails if global duplicate output already reliably identifies the exact affected record/field (it currently reports the duplicate declaration location, not that reference), or if this makes outputs materially harder to interpret.
