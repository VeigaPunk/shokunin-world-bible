## Three distinct questions

1. **Event-ID structural validity (the declared R70 gate):** The declaration says to require each side’s `event_id` to be a string with non-whitespace content before the pair comparison. The existing local check at `check_bible.py` lines 111–123 already diagnoses a non-dict side or a missing/non-string/blank ID, then `continue`s that side. The proposed pair gate is narrower than general reference validity: it gates on this event-ID predicate only, while retaining raw `field` equality comparison. It does not establish that the ID identifies any timeline row.
2. **Timeline resolvability (a separate downstream check):** For a side that passes local ID and field checks, lines 127–138 check whether the timeline table is available, whether the ID occurs exactly once, and then whether the unique event’s source is resolvable. These are index/status checks, not the R70 pair gate. An ID can be structurally valid but unknown, ambiguous, or unassessable because the whole timeline is unavailable. R62 documents the distinctions among unavailable, loaded-empty, partial, and duplicate timeline indexes (`reports/r62-scribe.md`, decision table; fixtures `r62-missing`, `r62-empty`, `r62-partial`, `r62-duplicate`).
3. **Field validity (an independent local check, intentionally not part of the R70 gate):** Lines 124–126 require a string field in `{'place_id', 'tick', 'depends_on'}` and stop that side’s timeline lookup if it fails. Round 70 expressly says to retain this allowed-field diagnostic and keep the existing raw field equality test. Consequently, when both IDs are nonblank strings and both raw fields match—even if that shared field is invalid—the declared R70 gate retains the pair-level `references must differ` finding. This preserves the R62 malformed-side behavior rather than adopting R69’s broader both-fields-valid gate.

The current pair condition at lines 139–143 only checks that both values are dictionaries and compares the two `.get()` values for equality. It therefore compares absent IDs/fields (`None == None`) as well as matching invalid values. Pair comparison is after side-local checks; a side’s `continue` does not skip the later pair check.

## Assessment and limits

The critical boundary is that **nonempty string ID is a shape predicate, not proof of event existence or uniqueness**. Conversely, invalid field does not make a nonempty ID structurally invalid under the declared R70 change. The R69 reports map a different, broader proposal that would have required both allowed field and nonempty ID; R69 rejected that proposal because it would remove the R62 malformed-side pair warning. R70 explicitly preserves that R62 warning by gating only on event-ID shape.

Test coverage presently includes the malformed-field/valid-ID R62 regression and a distinct valid-reference R62 control, but not committed matched cases for missing IDs, blank IDs, one invalid ID, or valid-identical references. Thus fixtures/reports support the code-path distinction and regression intent; they do not prove candidate output, calibration benefit, or regression safety. Any future candidate should compare full CLI exit/stdout/stderr tuples for missing, blank, one-invalid, R62 malformed-field, valid-identical, and valid-different controls, with timeline-loaded and unavailable variants where relevant. In particular, valid-identical is necessary to show that the pair warning remains for well-shaped duplicate references.

All findings here concern validation of supplied JSON ledger inputs and indexes. They do not establish that any event occurred, that a reference is supported by source text, or anything about canon, chronology, rights, or game mechanics.
