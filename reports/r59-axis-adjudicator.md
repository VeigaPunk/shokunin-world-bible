## Independent materiality and harms assessment

**Calibration — materially improved.** The old checker silently turned one raw repeated-member input into either a definite occupancy violation or CLEAN *solely because of member order*. It had no warning that a raw `place_id` was overwritten. The current checker refuses both orders with the same accurate input-ambiguity diagnostic; the matched unique control continues to exercise the actual occupancy rule. This is consequential for a reader deciding whether the input passed structural validation, not merely prettier presentation. It neither establishes which raw value was intended nor asserts any fictional location is true.

Rejecting **every** repeated JSON object member is a newly chosen strict input policy, not a rule proved by r5, prior row-ID ambiguity rounds, or a known upstream producer contract. A repeated equal-value nested member is not a conflicting story claim; the nested case shows that the rule rejects redundancy too. Nevertheless, no inspected contract promises last-wins or a supported duplicate-member producer convention. Silent selection makes raw validation dependent on Python's discarded key; a consistent rejection rule is reasonable for this validator, and the README explicitly states it. An authoritative last-wins convention would overturn this judgment.

The nested six dangling findings are a **real calibration cost**: because `entities.json` is unloaded, otherwise parseable relations/timeline rows cannot resolve references. Taken alone they could mislead. Here each finding is relative to loaded rows and is preceded by the file-level parse rejection; README and fixture explicitly explain they are not evidence of absent entities. This is existing whole-file unload behavior applied to a new parse class, not a new claim about world absence. It is noisy but bounded/documented and does **not** materially harm calibration on the evidence tested. Avoid claiming the hook knows `claims[i].source_id`, or that seven diagnostics represent seven independent source mistakes. A later narrow cascade-suppression improvement might help, but is not necessary for admission and should not be silently folded into this round.

**Depth — unchanged. Coverage — unchanged. Calibration — materially improved, no material harm demonstrated.** The checker now distinguishes a raw input ambiguity; it does not add source-text verification, evidence about lore, new narrative coverage, or adjudication of canon/chronology/rights/permission. Old-case exact preservation does not inflate depth or coverage. External duplicate-key producer conventions and untested inputs remain limits; the pinned 95 cases do not prove universal compatibility.

## Verdict

**ADMIT** this narrow calibration candidate: at least one axis materially improves, and none materially harms on available evidence. Keep the candidate checker, four fixtures, and README; do **not** recommend rollback. This is a parser policy/validator decision, not an interpretation of which `place_id` is correct, any in-world source support, actual chronology or fictional location, canon, rights, license, or permission.
