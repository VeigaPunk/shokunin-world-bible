# Round 21 schema scout — `depends_on` admission and member semantics

## Raw observations

- `FIELDS['timeline']['depends_on']` is `list`. The generic row gate admits a timeline row only when the field exists and `type(value) is list`; this rejects tuples and `null`, but admits an empty list and lists with arbitrary member types. The same gate requires `tick` to satisfy `type(value) is int` (so booleans are rejected) and other required values to have their exact declared types/nonempty-string constraints. A row failing any required field is excluded from `data['timeline']`, so it is not indexed or considered by occupancy/dependency passes.
- In the timeline pass, after dangling/ambiguous actor and place checks, source checking and negative-tick reporting, the checker tests `all(isinstance(dep, str) for dep in row['depends_on'])`. A single non-string appends `timeline[i].depends_on: expected event-id strings` and immediately `continue`s to the next timeline row. Thus an admitted list like `["a", None]` loses not only dependency lookup for all its members, but also later occupied-slot compare/store for the row. The early exit is after the current row's source/tick/identity diagnostics, but before both occupancy and dependency traversal.
- With the existing consistent corpus copied to a temporary directory, I ran the checked-in CLI using two otherwise known rows for `mira` at tick 4: `a` at `harbor`, then `b` at `tower`. With `b.depends_on=[]`, output includes `timeline[1]: double-booked 'mira' at tick 4 ...`. Changing only `b.depends_on` to `[null]` produces only `timeline[1].depends_on: expected event-id strings`; the booking finding is masked. The dependency-mixed probe `["a", null, "a"]` likewise produces only the type diagnostic: no booking, no inversion, and no repeated-dependency finding. These were temporary probes, not committed fixtures.
- The member-level dependency algorithm, when reached, walks list order with `seen_dependencies`: it reports self-dependency for a member equal to row ID; repeated members get a repeated-dependency finding and skip further lookup for that occurrence; each first-seen member is looked up against event ID counts and yields unknown (zero), ambiguous (>1), or, if uniquely resolved, timeline inversion when both endpoint ticks are nonnegative and prerequisite tick is greater than or equal to the current row tick. It does not treat the dependency list as a set for reporting repeats. An early list-wide type gate currently prevents all of these checks if any member is non-string.

## Recommendation (not implementation)

Keep the required-field rule that `depends_on` itself must be a list. Do not silently treat malformed members as valid IDs or pass them to dictionary/event lookup. Avoid a list-wide `continue` before independent occupancy validation: perform the existing guarded known-actor/known-place/nonnegative-tick occupancy check regardless of member validity, while retaining the malformed-list diagnostic. For dependency checks, handle members individually: report/skip a non-string member safely, and preserve existing traversal order, duplicate, self, unknown/ambiguous, and valid-endpoint inversion behavior for string members. Validate that recommendation with the paired empty-list/`[null]` booking probe, mixed valid+malformed dependency probes, and prior-output replay; this scout did not replay the 56 historical outputs.

This establishes checker-input behavior only. A checker occupancy finding does not establish sourced canon, and a malformed dependency value proves neither a dependency relationship nor event truth.
